# Deploy the isolated Hive platform

## Outcome

PR 794 was validated on its exact head, squash-merged, and deployed from the
exact merge commit through the repository Taskfile.

## Progress

- The production node runs k0s with Kata Dragonball and a four-replica Hive
  warm pool.
- Every worker is healthy with all five containers ready and zero restarts.
- The dispatcher and reaper controller are ready on the same immutable image
  digest.
- Kata isolation was verified by observing a guest kernel distinct from the
  host kernel.
- Neo4j is healthy with its retained 1 TiB volume, TLS, authentication, and
  default-deny network policies.
- The stable Kubernetes API route, persistent firewall fragment, and unique
  Nook-owned live rules passed the Taskfile status contract.
- Redis, the loopback image registry, and the TLS proxy are healthy.

## Implementation problems

- The original Hive workflow exported a multi-gigabyte toolchain image and
  rebuilt redundant Rust dependency profiles.
- Review exposed recovery ordering, standalone destructive-test defaults,
  firewall uniqueness, pipeline failure propagation, and scratch-export gaps.
- Each issue was fixed with a focused regression before the final exact-head
  validation.

## Decisions

Hive now follows the nook-app dependency and cache topology. Native Clippy and
test compilation run as sibling BuildKit stages, compiler objects use the
remote Redis sccache backend, test execution exports only stripped executables
through scratch, and pull requests consume but do not publish the shared
BuildKit cache.

The final hosted Hive workflow completed in 6m44s. Its compiler critical path
was approximately four minutes, with 1,970 remote compiler cache hits and zero
misses across Clippy and test compilation. The exported test payload was 177 MB
instead of a multi-gigabyte toolchain image.

## Validation

- `task infra:k0s:manifests:check`
- `task format`
- exact-head PR workflow
- exact-head Hive workflow
- `task pr:ready PR=794`
- `task infra:deploy`
- Taskfile-owned k0s, infrastructure, Redis, and Hive production diagnostics

Browser and extension end-to-end suites remained intentionally deferred for a
future iteration, per the delivery decision.

## Remaining work

The deferred browser and extension end-to-end suites remain future work. The
isolated Hive platform itself is complete and operating.
