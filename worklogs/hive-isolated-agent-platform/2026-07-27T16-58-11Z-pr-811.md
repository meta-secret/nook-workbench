# Deliver task-scoped Hive filesystem publication

## Outcome

PR 811 replaced the sandbox-side Unix socket with an ephemeral filesystem
mailbox exposed only to its Main-repair task. The relay acknowledges the exact
request digest, the client authorizes that acknowledgement with a one-time
secret, and the relay rechecks the immutable processing bytes before forwarding
anything to the credential-owning broker. Responses remain signed and bound to
the same request identifier and digest.

PR 813 corrected the live diagnostic for OpenSSL's one-shot Ed25519 input
contract. Both changes were merged and deployed from exact Main commits. The
active cluster now runs the corrected immutable image across four Dragonball
workers.

## Progress

- Added an explicit ephemeral writable mailbox root without making credentials,
  broker streams, or the private publication checkout visible to Codex.
- Added acknowledgements and commits so substituted requests are rejected
  before the broker receives any bytes.
- Bounded broker readiness and mailbox authorization waits.
- Added lossless, bounded continuation for truncated check, review, comment,
  and review-thread inspection records.
- Preserved deterministic branch publication, targeted review replies, exact
  head checks, squash merge, and Main verification.
- Updated the architecture contract, operator documentation, manifest
  invariants, and the live Bubblewrap smoke.

## Implementation problems

Review identified four final boundary gaps: the mailbox was not an explicit
writable root, a substituted request could reach the broker before digest
verification, bounded inspection could discard detail, and broker readiness
could wait indefinitely. The final PR head addressed all four and passed the
repository-owned workflows.

The first production smoke then exposed that OpenSSL cannot determine the size
of piped input for one-shot Ed25519 signing. PR 813 changed the diagnostic to
use a private bounded input file and remove it immediately after each
signature. The repeated production build reused the entire Rust dependency,
source, and binary graph.

## Decisions

The filesystem mailbox is a capability transport, not shared agent state.
Agents coordinate through Neo4j and public Workbench records. The trusted
broker continues to own credentials and enforce typed task policy.

The exact-request authorization handshake is required before any broker
execution. A signed response alone is insufficient because a malicious
filesystem writer could otherwise substitute a privileged request before the
trusted client detects the changed digest.
