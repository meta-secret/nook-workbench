# Skip deferred E2E-only Hive handoffs

## Outcome

PR 809 made Main-failure handoff generation-aware and policy-safe. Deferred
browser E2E-only reruns now retire active and failed repair generations without
allowing release retries to resurrect them. Actionable reruns retain their
latest evidence until the preceding generation terminates.

The exact merge was deployed to the production Dragonball cluster as immutable
digest `sha256:5a21a995f478dbf0fdcc008c5f9062740448fd0dcfffbcfc8f18015dda48278b`.

## Progress

- Added stale workflow-attempt rejection before either incident mutation path.
- Added generation-specific plans, worklogs, timestamps, and task identifiers.
- Prevented active-delivery suppression from permanently consuming newer
  incident evidence.
- Made policy retirement include failed roots so release retries cannot rearm
  obsolete work.
- Split Hive test and Clippy dependency materialization for parallel cache
  reuse and removed oversized test-image export.
- Updated Hive architecture, CI, quality, and pull-request documentation.

## Implementation problems

Two Main advances required fresh exact-head verification. Review identified
ordering races in active delivery suppression, stale rerun arrival, generation
timing, and failed-task policy retirement; all were fixed before merge.

## Decisions

E2E checks remain visible in Main, but E2E-only failures are deferred from the
autonomous repair queue for this iteration. Main remains the trusted cache
producer, while pull requests restore its cache read-only.

## Validation

- Exact-head PR, Hive, native, WASM, and preview checks passed.
- `task pr:ready PR=809` returned ready with zero unresolved conversations.
- Main Hive verification published the split cache graph successfully.
- Production reports four 5/5-ready workers with zero restarts.
- Dragonball guest-kernel isolation, seccomp, Bubblewrap, publication
  descriptor inheritance, Neo4j connectivity, dispatcher, and reaper checks
  passed.

## Remaining work

Browser, UI-demo, and extension E2E failures remain explicitly deferred to a
future product-test iteration.
