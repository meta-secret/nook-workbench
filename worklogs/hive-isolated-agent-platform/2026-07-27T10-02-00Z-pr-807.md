# Make Hive leases resilient and observable

## Outcome

PR 807 replaced the five-minute execution lease with a one-hour lease renewed
every minute, exposed ordered current and previous attempt failures, and
expanded Taskfile diagnostics across every worker pod and container. The exact
merge was deployed to the production Dragonball cluster.

## Progress

- Added accepted-heartbeat evidence to the worker lifecycle.
- Added latest and previous attempt state to durable queue status.
- Added production Neo4j regression coverage for attempt ordering.
- Expanded bounded diagnostics across the four-worker pool.
- Rearmed the retained exhausted Main incident once for the deployed release.

## Implementation problems

The old five-minute lease repeatedly reclaimed healthy Codex turns before they
could diagnose, validate, and publish a complete repair. A concurrent Main
cache-policy change also caused one cold local formatting setup, while the
dedicated Hive workflow remained fully backed by Redis.

## Decisions

The lease is long enough for a full agent turn but is still renewed every
minute and remains protected by owner and token checks. Release-scoped retries
stay bounded. Browser, UI-demo, and extension E2E failures remain deferred and
are not treated as part of this infrastructure recovery.

## Validation

- Exact-head PR, Hive, native, WASM, and preview checks passed.
- The Hive workflow selected the persistent TLS Redis service and reported
  1,910 cache hits with zero misses or cache errors.
- `task pr:ready PR=807` returned ready with zero unresolved conversations.
- Production runs digest `sha256:77ef6b5b71ed8e0778d3f90605281e02d364f8478ad4b86e272a5ba8f320d7b8`.
- Four workers are 5/5 ready with zero restarts; Dragonball, seccomp,
  Bubblewrap, broker-descriptor, Neo4j, dispatcher, and reaper checks passed.

## Remaining work

The deferred E2E-only Main failures remain future product-test work. Active
repair turns are retained by the new long lease instead of being discarded
after five minutes.
