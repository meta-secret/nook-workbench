# Fix Hive Bubblewrap publication descriptors

## Outcome

PR 806 fixed the worker's Bubblewrap descriptor mapping so the capability-only
publication client works from the nested Codex sandbox without exposing a token
or enabling direct GitHub networking.

## Progress

- Replaced the incompatible inherited descriptor mapping with the supported
  Bubblewrap shape.
- Added a production-image smoke probe for descriptor passage through the
  nested sandbox.
- Preserved the deny-by-default network and filesystem profiles.

## Implementation problems

The first live retry proved that the broker socket itself was healthy but the
descriptor inherited by the sandbox was invalid. The fix was deliberately
narrow and retained the same capability boundary.

## Decisions

Publication remains brokered over a local Unix socket. No Docker-in-Docker,
host bridge alias, credential mount, or direct worker egress was introduced.

## Validation

- Exact-head PR and Hive workflows passed.
- The Hive workflow reported 1,910 remote Redis compiler hits and zero misses.
- The production Bubblewrap publication-descriptor smoke probe passed.
- `task pr:ready PR=806` passed before squash merge and deployment.

## Remaining work

Long agent turns still exceeded the five-minute task lease, so lease resilience
and live queue observability were completed in PR 807.
