# Provision Rise-S ARC worker capacity

## Outcome

PR 1083 merged a second k0s node dedicated to ephemeral Kata ARC compute. It
also replaced the verified-cache registry publication tail with private,
generation-checked copy-on-write BuildKit state on local solid-state storage.

Both ordinary and Hive scale sets remain elastic from zero to ten. Controller,
listener, registry, and other storage-authority workloads remain pinned to the
existing cluster node.

## Progress

- Provisioned the purchased compute node with stable Debian and joined it to
  k0s over the cluster's private WireGuard network.
- Qualified the pinned Kata QEMU runtime with a real guest-kernel smoke test.
- Added deterministic TypeScript, Rust, and Taskfile-governed worker contracts.
- Configured a 32 GiB sparse BuildKit filesystem per job with Btrfs reflink
  cloning and stale-generation protection during seed promotion.
- Preserved storage and Kata node labels during re-registration and repaired
  Zot startup recovery after its content scan exceeded the old probe window.
- Removed the superseded hosting-price collector and local price database.
- Added the provider-operation hard rule that reusable credentials are saved
  automatically under `~/.nook` with private directory and file permissions.
- Audited workflow routing. Trusted heavy work uses `nook-k0s` or
  `nook-k0s-hive`; intentionally untrusted, release, deployment, browser, and
  fallback lanes remain on GitHub-hosted runners.

## Implementation problems

- Node re-registration dropped the storage label and temporarily removed the
  registry endpoint. Worker automation now preserves storage and Kata labels,
  and the legacy all-node label mutation was replaced with exact-node targeting.
- The registry's startup content scan exceeded the probe budget. The startup
  threshold now permits recovery without weakening steady-state health checks.
- Small Hive BuildKit memory limits failed during Rust linking. Focused smoke
  runs established a 4 GiB BuildKit budget, which passed the exact-head Hive
  verification without host-memory overcommit.
- Kata's original RuntimeClass overhead understated the QEMU guest envelope.
  The final overhead and container limits leave host headroom while admitting
  ten ordinary runners.

## Decisions

- Keep runners fully ephemeral; retain build state, not runner Pods.
- Continue to prohibit Docker-in-Docker, Sysbox, host Docker sockets, and a
  shared writable BuildKit daemon.
- Use a private 32 GiB sparse disk per job. Reflinks share unchanged extents, so
  provisioning does not copy the logical filesystem size.
- Treat ten ordinary runners or seven fully saturated Hive runners as the safe
  capacity of one 64 GiB compute node. Additional heavy Hive jobs queue safely;
  another equivalent compute node raises parallel heavy capacity horizontally.

## Validation

- Exact-head Hive smoke run 32620006296 passed and promoted reusable cache state.
- Exact-head ordinary preflight run 32620238859 passed with clean Kata teardown.
- Ten exact-head `arc:runtime` runs completed concurrently without failure.
- Complete PR validation run 32620493819 passed all required Rust, WASM, web,
  policy, coverage, and preview gates.
- `task pr:ready PR=1083` passed on the current base with no unresolved threads.
- PR 1083 squash-merged as the first Main commit containing the worker contract.

## Remaining work

None for this delivery. Add equivalent compute nodes when seven simultaneous
Hive jobs or ten simultaneous ordinary jobs become sustained rather than burst
load.
