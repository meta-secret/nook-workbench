# Preserve Hive publication capability across Codex sandbox

## Outcome

PR 810 replaced the inherited publication descriptor that embedded Codex closes
at its shell boundary with an ephemeral task-bound Unix socket relay. The
capability remains unavailable to non-repair tasks, uses a private `0700`
directory and `0600` socket beneath the bound worker workspace, and connects
only to the typed publication broker.

The exact merge was deployed to the production Dragonball cluster as immutable
digest `sha256:07279ee54b4ac3e05574d50531f8871576f9c8c7b7a408d2fbd265d03bbac26a`.

## Progress

- Preserved the publication capability through the embedded Codex shell
  boundary without changing the pinned Codex dependency.
- Preconnected each broker stream before accepting one sandbox client, so
  abandoned requests cannot shift later replies.
- Replaced the descriptor-only diagnostic with a real `hive github ping`
  through the production Bubblewrap shape.
- Kept the capability beneath `/workspace`, which remains visible when
  Bubblewrap replaces `/tmp`.
- Added bounded diagnostic client and broker timeouts so a failed isolation
  check reports instead of hanging.
- Confirmed the trusted local and production build paths receive the existing
  direct-TLS Redis compiler-cache credential as a BuildKit secret.
- Updated the Hive architecture, runtime, manifest contract, Taskfile
  diagnostics, and operator documentation.

## Implementation problems

The original inherited descriptor survived direct Bubblewrap execution but was
closed by embedded Codex before its shell child started. Review then identified
that the first socket implementation lived beneath the outer `/tmp`, which the
real sandbox masks, and that its failure diagnostic could block indefinitely.
Both findings were fixed and revalidated before merge.

## Decisions

The capability is a local Unix socket rather than a network endpoint or
credential. Random task-local placement and filesystem permissions limit its
scope, while the broker continues to enforce the typed, task-bound publication
protocol. No GitHub or Redis credential is exposed to the agent.

## Validation

- Both exact-head PR and Hive workflows passed after the review fixes.
- `task pr:ready PR=810` returned ready with zero unresolved conversations.
- `task hive:verify` passed 51 tests.
- `task infra:k0s:manifests:check` passed.
- The production build reused all toolchain and cargo-chef dependency layers;

- Production reports four 5/5-ready workers at rollout completion with zero
  restarts.
- Dragonball guest-kernel isolation, guest seccomp, the exact Bubblewrap shape,

- The failed chain previously blocked by `Bad file descriptor` was rearmed for
  the new release and progressed into running repository work instead of
  immediately returning the old capability error.

## Remaining work

Browser, UI-demo, and extension E2E failures remain explicitly deferred to a
future product-test iteration. Rearmed durable repair chains continue under
Hive's normal lease and retry lifecycle.
