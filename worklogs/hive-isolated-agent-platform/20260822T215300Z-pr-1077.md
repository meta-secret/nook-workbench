# Trusted Main ARC routing delivery

## Outcome

Merged PR 1077. Every trusted Main job now selects the configured `nook-k0s`
route, and the deployed general and Hive ARC scale sets each retain capacity ten
with scale-to-zero ephemeral Kata QEMU runners.

The repository also has a hard no-Python rule backed by Rust preflight. The
remaining Python automation was replaced with TypeScript and Bun or Rust.

## Progress

- Added an isolated Podman Docker API sidecar for Main browser workloads without
  Docker-in-Docker, Sysbox, or a host Docker socket.
- Kept private per-job BuildKit in each Kata VM with a 32 GiB copy-on-write
  state image and a 24 GiB sparse Podman store.
- Deployed ARC 0.14.2 and proved ten fresh general-runner pods can exist
  concurrently.
- Routed Hive Rust verification through the dedicated `nook-k0s-hive` scale set.
- Replaced repository Python scripts and packages with TypeScript/Bun or Rust,
  then added a hard repository-language invariant.

## Implementation problems

- Podman initially failed because `fuse-overlayfs` could not access `/dev/fuse`
  in the Kata guest. A sparse ext4 loop image with native overlay solved the
  Docker API and shared bind-mount contracts.
- A superseded Main run ignored normal and force-cancel requests while publishing
  cache. Its exact disposable ARC runner was deleted so current Main could run.
- Live merged-run evidence showed the remaining delay is cache serialization and
  HDD I/O, not ARC placement: Hive spent 13m16s verifying and 18m21s publishing
  verified cache.

## Decisions

- Keep every job in its own Kata QEMU microVM and discard its writable state.
- Keep maximum concurrency at ten and retain no idle runners.
- Use native overlay inside a dedicated sparse ext4 Podman store; never use DinD.
- Track cache publication and native Rust critical-path work independently from
  the completed routing change.
