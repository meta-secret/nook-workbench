# Hive ARC QEMU stabilization delivery

## Outcome

Switched ephemeral Hive ARC runners to the already-qualified Kata QEMU runtime
after normal Dragonball workload repetitions lost their sandbox. PR 1076 is
merged and its exact merge is deployed. Persistent Hive workers remain on
Dragonball.

## Progress

- Preserved one fresh Pod and microVM per job, private privileged BuildKit,
  32 GiB copy-on-write state, scale-to-zero behavior, and ten-runner capacity.
- Updated render contracts, repository documentation, and Cortex runtime
  guidance to encode the evidence-backed fallback.
- Deployed the PR head for production qualification, then redeployed the exact
  squash merge `96ed258e0f`.
- Completed a fresh PR Hive job in 2m10s. Rust verification took 1m39s.
- Completed exact-merge Main Rust verification in 1m04s on `nook-k0s-hive`.

## Implementation problems

- A cancelled diagnostic attempt left an ephemeral Dragonball runner unsuitable
  for timing evidence; the exact cancelled Pod was deleted before a fresh run.
- A normal fresh Dragonball run then lost its sandbox and could not resume the
  claimed GitHub job. That independent failure triggered the allowed QEMU
  fallback.
- Main-only registry cache publication remains a separate phase from Hive Rust
  verification and must not be counted as compilation latency.

## Decisions

- Use Kata QEMU for both ephemeral ARC scale sets because it completes the
  isolated workload reliably. Keep Dragonball for the persistent Hive workers.
- Keep 32 GiB private BuildKit images. Observed high-water use makes 24 GiB too
  narrow for publication and garbage-collection headroom.
- Keep fresh runners and copy-on-write seed clones. No Docker-in-Docker, Sysbox,
  retained runner, or shared writable BuildKit service was introduced.

## Validation

- Full format, ARC manifest contract, ARC render contract, Cortex audit, focused
  hosted preflight, exact-head PR validation, and session cleanup passed.
- The exact-head Cloud Codex review was clean and no review threads existed.
- `task pr:ready PR=1076` reported ready at `0d7207e1ea`.
- Production selected `kata-qemu-runtime-rs` for `nook-k0s-hive`; both scale
  sets remain dispatch-ready with maximum capacity ten.

## Remaining work

- Track Main-only registry publication latency separately. It preserves hosted
  fallback portability but is not part of the now-fast Hive verification step.
