# Complete trusted Actions ARC migration delivery

## Outcome

Merged PR 1080. Every job in all 19 GitHub Actions workflow files now has an
explicit typed runner-placement classification. Trusted build workloads use
`nook-k0s` or `nook-k0s-hive`; GitHub-hosted execution remains only for explicit
trust, deployment, AI-agent, scheduled, or runtime-specific boundaries.

## Progress

- Added an exhaustive TypeScript and Bun runner-placement inventory that fails
  on new workflows, new jobs, unexpected `runs-on` values, or invalid Main ARC
  triggers.
- Added the inventory to repository policy for every workflow or placement
  contract change.
- Corrected same-repository Dependabot routing in PR, Rust ecosystem, and Hive
  workflows by using immutable pull-request author identity.
- Proved six general ARC jobs ran concurrently on distinct disposable Kata
  runners and Hive Rust ran on the dedicated Hive scale set.

## Implementation problems

- Exact-head review found that workflow placement changes did not always run the
  static inventory and that Main ARC classification did not validate triggers.
  Both findings were fixed, replied to, and resolved.
- A canceled disposable ARC runner did not terminate and blocked the final run.
  Its exact pod was deleted; no persistent build state was affected.
- Repository policy rejected an authored raw string union. Runner placement is
  now modeled as a named TypeScript enum.

## Decisions

- Do not move untrusted fork or Dependabot execution onto the private cluster.
- Keep release, deployment, AI-agent, scheduled, and required hosted-runtime
  work on GitHub-hosted runners.
- Keep the legacy `nook` cleanup lane separate because it manages the persistent
  classic Docker runner pool rather than ARC delivery jobs.
- Make the executable placement inventory the authority instead of duplicating
  the classification in Cortex prose.
