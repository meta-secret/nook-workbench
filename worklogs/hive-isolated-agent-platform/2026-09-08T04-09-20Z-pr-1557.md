# Work summary

## Outcome

Dependency-policy checks retain only small results while preserving fresh security validation. The owning nightly declaration is prewarmed once in the immutable tools stage. PR 1557 was squash-merged as e7aadef71b3452d2b253ef621340e8ac16515415.

## Progress

- Used a disposable seeded Cargo home with cleanup on shell exit.
- Moved nightly installation before the per-run nonce after the first runtime proof exposed residual toolchain downloads.
- Added a focused test owner and documented the retention invariant.

## Implementation problems

- Each old policy result retained approximately 1.9 GiB of registry and Git source data.
- The initial cleanup exposed another 1.4 GiB of nightly installation in one workspace. Immutable prewarming removed that repeated download and retained result.
- A source assertion alone could not prove filesystem behavior; settled BuildKit records and physical snapshot inspection supplied runtime evidence.

## Decisions

- Preserve the nonce and fresh security checks.
- Keep existing cache limits and trust boundaries.
- Allow ordinary garbage collection to reclaim old records rather than clearing useful caches.
- Hard cancellation can bypass shell cleanup. Policy source downloads still occur; this change does not claim to eliminate all network traffic.
