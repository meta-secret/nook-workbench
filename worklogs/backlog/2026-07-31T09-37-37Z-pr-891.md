# Merged Brave iCloud second-popup fix

## Progress

- Confirmed CloudKit Production allowlist accepts `simple.dev.nokey.sh`.
- Diagnosed Brave race: native Apple window opens, then a second `window.open`
  fallback is blocked and surfaces immediate sign-in failure.
- Shipped wait-on-existing-window path, extracted web-auth wait helpers, updated
  the iCloud provider demo, and squash-merged PR 891 after exact-head validation.

## Problems

- Initial Verify failed on missing UI demo contract and an authored `undefined`
  token in the demo stub; both fixed before merge.
- Branch needed rebase onto moving `main` before readiness passed.

## Decisions

- After a native CloudKit button click, never open a second Apple auth popup;
  wait for token store or postMessage from the existing window.
- Keep Brave direct Web Services auth only for programmatic clicks.
