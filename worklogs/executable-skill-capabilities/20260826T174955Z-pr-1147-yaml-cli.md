# Merge the executable-skill YAML command protocol

## Outcome

PR [#1147](https://github.com/meta-secret/nook/pull/1147) merged a reusable,
self-describing YAML command boundary for executable skills. Agents and humans
can list finite domain actions, inspect exact schemas and examples, submit a
YAML document, and receive YAML-only results and bounded diagnostics.

## Progress

- Added shared typed action discovery, YAML decoding, invocation, diagnostics,
  and result primitives under `.agents/skills`.
- Migrated the Cortex article-structure capability to the shared command
  interface without changing its article audit behavior.
- Added `task skills:tools-list` and `task skills:run CONFIG=...` entrypoints.
- Enforced executable-skill formatting, lint, TypeScript, source structure, and
  focused behavior tests through the package verification path.
- Documented the protocol in the root README, owning Cortex workflow, dynamic
  skill card, and executable skill instructions.

## Implementation problems

- Review found that early discovery schemas and request/result transport bounds
  were not exact enough. The schemas now publish supported variants, recursion
  and size bounds, request byte limits, and derived result constraints.
- `origin/main` advanced during final delivery with a delegation policy fix and
  the separately owned executable-skill closure rollback. Both changes merged
  cleanly, and the final head received replacement exact-head validation.

## Decisions

- Reuse Loom's domain-YAML discovery and invocation model without coupling
  executable skills to Loom's application command registry.
- Keep providers finite, static, deterministic, and read-only. The CLI is an
  invocation contract, not a process sandbox or runtime activation mechanism.
- Leave the executable-skill registry, closure, analyzer, containment, and
  activation work out of this PR.
