## Implementation problems

- Review found that activation needed to clear outgoing identity state and refresh the selected identity's protection status. The transition now fails closed if that refresh fails.
- Review found that the decision path used a permissive event-store reader. A dedicated read-only strict wrapper now rejects incomplete or malformed local history without changing ordinary loading semantics.
- Repository policy rejected a separate Rust unit-test module. The behavior tests were colocated with the focused implementation.
- The first final Web validation found one raw canonical translation key in a mounted test. It was replaced with the generated typed key before the successful exact-head run.

## Decisions

- Only an exactly pristine local genesis is replaceable; ambiguous, malformed, unavailable, or valuable local state is never recommended for replacement.
- Identity eligibility is domain-owned and public-only. Protection ceremonies still determine whether access actually succeeds.
- Provider credentials never transfer between app-ID identities. Import completes durably before a separate terminal identity activation.
- This flow preserves distinct valuable vaults separately and does not implement event-log or secret-level merging.
