# Extract nook-event-log crate

## Outcome

Extracted Nook's signed causal vault history into the portable
`nook-event-log` crate and squash-merged PR 793. The new dependency direction is
`nook-auth2 + nook-replication -> nook-event-log -> nook-core -> nook-wasm`.

## Progress

- Moved canonical events, signing, authorization graph, deterministic
  projection, epochs, fingerprints, and store orchestration out of `nook-core`.
- Preserved persisted formats and compatibility type/module paths through
  `nook_core` re-exports.
- Assigned event-domain errors to `nook-event-log` and kept conversion to
  `VaultError` at core application-service boundaries.
- Audited TypeScript and confirmed it contains host lifecycle, presentation, and
  provider/browser I/O rather than duplicated event-log policy.
- Added the crate to workspace, Docker, native/WASM, coverage, cache hashing,
  historical coverage, preflight, Task, workflow, and architecture surfaces.

## Implementation problems

- The first PR run exposed preflight rustfmt ordering; host formatting was
  applied before the next push.
- Historical base coverage initially combined a pre-extraction core manifest
  with current source. The fallback now preserves the base core manifest while
  copying current workspace metadata and newly introduced portable crates.
- Review identified that WASM invalidation omitted crate manifests. Both mounted
  and Docker-seeded hashes now include workspace metadata and all portable crate
  manifests, with a preflight invariant that checks the inputs semantically.
- A review questioned `VaultResult` compatibility. Duplicating the complete
  event type graph would defeat extraction, so event-domain APIs intentionally
  return `EventResult`; application services convert errors at the core boundary.

## Decisions

- Use `nook-event-log`, not `nook-event-sourcing` or `nook-commit-log`.
- Keep generic causal/replica mechanics in `nook-replication`.
- Keep provider transports, OAuth, IndexedDB, browser APIs, and UI lifecycle in
  host adapters.
