# Extracted portable replication mechanics

## Outcome

Nook now has a portable `nook-replication` Rust crate for generic causal DAG
indexing, append-only replica storage, per-provider outboxes, and missing-event
repair planning. `nook-core` retains signed vault event bytes, schemas,
authorization, projection, and key epochs; `nook-wasm` retains provider I/O.

## Progress

- Added the sibling foundation dependency shape
  `nook-auth2 + nook-replication -> nook-core -> nook-wasm`.
- Preserved the public `nook_core` compatibility API and persisted vault-event
  serialization while delegating generic mechanics.
- Added 16 focused replication tests and retained the existing core and WASM
  behavioral suites.
- Wired the crate through workspace manifests, native/WASM Docker builds,
  coverage, cache inputs, Task commands, preflight invariants, and architecture
  documentation.
- Addressed every current-head review finding and merged
  [Nook PR #791](https://github.com/meta-secret/nook/pull/791) as `61630537`.

## Implementation problems

- The PR base predated the new crate, so the coverage fallback could not build
  the historical source with the current package graph. The workflow now copies
  the extraction-aware Bake graph and dependency-only manifests while keeping
  base `nook-core` Rust source unchanged.
- One coverage fallback attempt hit a transient one-second BuildKit solve
  failure. A later changed head established a fresh successful comparison; no
  unchanged product-validation rerun was used.
- Review exposed order-dependent parent conflicts, transitive pending and
  quarantine propagation gaps, cycle handling and complexity, immutable-byte
  conflicts, and outbox preservation. Each finding received a focused
  regression before resolution.
- `main` advanced twice during delivery. Both bases were integrated before
  fresh exact-head validation.

## Decisions

- Use the narrow name `nook-replication`; `nook-distributed` would imply
  networking, consensus, or membership ownership that this crate does not have.
- Keep the extracted crate provider-neutral and application-neutral: typed IDs,
  parent relationships, opaque immutable bytes, outbox bookkeeping, and repair
  set calculation only.
- Keep domain authorization, signatures, canonical serialization, projection,
  key epochs, provider credentials, and transport lifecycle outside the crate.
- Prefer deterministic canonical conflict resolution and derived quarantine
  recomputation over arrival-order-dependent state.
