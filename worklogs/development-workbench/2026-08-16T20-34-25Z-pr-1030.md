# Replace scheduled agent polling with explicit dispatch

## Outcome

Removed the scheduled Agent implement poller and replaced its repository-wide
issue discovery with explicit dispatch. Nook PR 1030 preserves prompt-backed
work and direct issue-backed claiming while rejecting dispatches that supply
neither input or both inputs.

## Progress

- Claimed the focused Workbench issue as `cypherkitty` before changing Nook.
- Branched from current `origin/main` and limited the PR to the workflow,
  preflight contract, and affected Cortex workflow documentation.
- Removed the schedule, recursive tree API, all-issue read loop, and workflow
  concurrency group that could discard an older explicit dispatch.
- Preserved eligibility, ownership, write-permission, continuing-owner, atomic
  claim, Docker, planning, implementation, PR assignment, and Workbench-result
  behavior.
- Updated preflight coverage to require both dispatch rejection clauses,
  direct content lookup, removed scanning constructs, and fail-closed workflow
  ordering anchors.
- Replied to and resolved the single actionable review thread before the final
  exact-head validation cycle.
- Squash-merged PR 1030 as
  `132a25f3524f3480c7985dd75a90a86d2dfc417d`.

## Implementation problems

- Local advisory review found that claiming before checkout could strand an
  issue if checkout failed because the failure publisher would be unavailable.
  Checkout now follows input validation and precedes the atomic claim.
- Local advisory review found that GitHub workflow concurrency retains only
  the newest pending run. The concurrency group was removed so explicit
  dispatches are not silently dropped; atomic blob-SHA claims still serialize
  duplicate issue work.
- The first PR validation run hit transient short reads while importing
  registry and BuildKit cache data. A review fix changed the head afterward,
  and the mandatory replacement exact-head run passed completely.
- Review found that Rust `Option` ordering could let missing workflow anchors
  satisfy order assertions. Every anchor now resolves with `anyhow::Context`
  before numeric positions are compared.

## Decisions

- Keep `workflow_dispatch` as the only trigger and require exactly one of
  `issue_path` or `prompt`.
- Resolve `issue_path` with one direct Workbench content request.
- Keep `automation: manual` on the repair record because the issue was
  explicitly assigned and claimed.
- Do not add a cross-repository secret or an event dispatcher in this PR.
- Keep all plan, implementation, pull-request assignment, and Workbench result
  stages unchanged after preflight.
