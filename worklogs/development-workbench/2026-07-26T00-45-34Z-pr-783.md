# Migrate Nook development context into Workbench

## Outcome

Created `meta-secret/nook-workbench` and made it the versioned system of record
for Nook issues, agent worklogs, AI-agent statistics, and Main-build
statistics. Nook PR 783 migrated the development workflow and removed `.stats`;
the legacy Nook GitHub Issues surface was disabled after the merge.

## Progress

- Imported 152 historical GitHub issues with bodies and comments into feature
  directories, retaining all imported records as manual automation.
- Migrated 148 historical AI-agent and Main-build statistics records.
- Added strict Workbench validation for issue metadata, worklog structure, and
  changed statistics.
- Updated `.cortex`, agent skills, CI-agent prompts, preflight tests, and GitHub
  Actions to claim Markdown issues and publish worklogs and statistics here.
- Merged Nook PR 783 at exact head after four PR workflow runs and two rounds of
  review hardening.
- Fixed GitHub's skipped-job timestamp skew in the Main statistics collector
  through Nook PR 785.
- Fixed rerun collection to exclude successful jobs carried forward from prior
  attempts through Nook PR 787.
- Added Bun-powered versioned Git hooks and a GitHub validation gate for
  sensitive content, then enabled GitHub secret scanning and push protection.

## Implementation problems

- Cross-repository GitHub issue events do not provide the required trusted
  write path; scheduled polling plus an atomic explicit claim was used.
- PR 776 merged while the migration was open and added a final legacy
  statistic. The migration was rebased, the record was moved here, and its
  invalid derived local-duration total was corrected.
- Review found failure-after-claim, timeout, stale-write, immutable-statistics,
  dispatch ambiguity, fallback-shape, and agent-summary secret risks. Each path
  was hardened and covered by focused preflight assertions.
- One local format/build attempt and one intermediate PR run were superseded
  during the late-statistics reconciliation; fresh exact-head runs passed.
- The first production Main statistics collector encountered a one-second
  reversed timestamp on a skipped job. The follow-up accepts that narrow
  GitHub rounding case as zero duration while executed jobs remain strict.
- A failed-job rerun returned successful jobs from attempt 1 in GitHub's
  attempt-2 jobs response. The follow-up scopes timing and job metrics to work
  actually executed in the requested attempt.

## Decisions

- Only `status: ready` together with `automation: agent` authorizes automatic
  execution; all historical imports remain manual.
- Every task-owning agent publishes a structured worklog, with trusted fallback
  metadata when the authored summary fails validation.
- Statistics use unique immutable paths and publish directly to Workbench.
- Existing mutable issue and worklog updates require the exact base blob SHA to
  prevent lost concurrent edits.
- Public Workbench records retain durable engineering context but omit raw
  output and unnecessary operational detail.
