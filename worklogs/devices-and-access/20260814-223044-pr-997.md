# Portable identity directory and staged handoff

## Outcome

PR 997 delivered the first independent identity-management slice. Rust now
owns a migration-safe directory of identities, explicit local selection,
identity-owned vault DEK envelopes, and typed WASM operations for list, create,
and select. Vault creation consumes the selected identity without moving
policy into TypeScript.

## Progress

- Replaced singleton identity persistence with a validated Rust directory.
- Preserved legacy identity ids, app-key membership, and vault ownership.
- Split production responsibilities so every changed source file remains at or
  below 750 lines.
- Added active signed-roster reconciliation for identity-owned vault grants.
- Added an explicit existing-vault import handoff state.
- Made fresh-vault identity adoption crash-safe with an inactive, resumable
  genesis transaction.

## Implementation problems

- Early handoff publication required snapshot rollback. Review showed that a
  crash, concurrent tab update, or partial event-log write could make that
  rollback unsafe.
- The final design leaves active identity state untouched until verified
  connect. It resumes partial genesis from a durable marker and publishes the
  directory plus matching signer in one compare-and-write transaction.
- Existing-vault imports originally shared the fresh-vault state. A distinct
  Rust state now defers enrollment until verified connect establishes the
  owner and validates the active signed roster.

## Decisions

- Portable identity policy, state transitions, validation, and persistence
  remain in Rust. TypeScript owns browser lifecycle orchestration only.
- Event stores are never rewound after partial genesis.
- Concurrent identity changes fail closed instead of being overwritten.
- Provider labels remain evidence-aware and are not inferred from WebAuthn.
- Mobile application work is excluded; the Rust boundary is reusable by later
  platform hosts.
