# Adopt the chain-strength Devices and access experience

## Outcome

The production **Devices & access** dashboard now uses the relationship-first
chain-strength concept while retaining Nook's existing light and dark theme.
The surface anchors the current browser or paired device, presents the observed
unlock identity as a distinct object, and gives each vault an honest verified
or unverified access row backed by production state.

## Progress

- Replaced the original access diagram with a responsive strength map and a
  truthful unprepared/recovery preview.
- Preserved the existing typed dashboard boundary and separated browser facts,
  user-supplied passkey labels, Nook-verified device-to-vault relationships, and
  unknown metadata.
- Kept vault routes behind the selected Vaults tab, retained progressive
  technical details, and restored focus predictably across navigation and save
  recovery.
- Added localized English and Russian copy plus unit, Playwright, and recorded
  UI-demo coverage for empty, passkey, PIN, companion, locked, recovery, and
  missing-metadata states.

## Decisions

- The research experiment supplied hierarchy and interaction evidence, not
  literal colors, mock controls, fixed data, or provider claims.
- `Named by you` appears only when a passkey/provider label is actually known;
  PIN, companion, and unnamed-passkey facts remain system-derived or unknown.
- Verified vault rows attribute access to the device key, not to a browser-
  observed credential fingerprint or user-entered provider reminder.
- The tablist owns only the three selectable links; vault route details render
  as sibling content associated with the selected Vaults panel.
