# Switch between identity list and graph views

## Outcome

Devices & access now presents the selected identity as one representation at a
time. List is the default key inventory; Graph is the relationship canvas.
The localized representation switch preserves Nook's existing visual language.

## Progress

- Added the shared selected-identity header and List/Graph switch.
- Made List and Graph mutually exclusive while preserving identity selection,
  locked evidence, and remote-identity fallback behavior.
- Made inventory inspection open Graph in the identity perspective and focus
  the corresponding protector or app-key node.
- Updated English and Russian catalogs, the product specification, unit tests,
  UI demo coverage, and Playwright flows.

## Implementation problems

- Review found focus loss when the selected list row unmounted. The transition
  now waits for Svelte rendering before focusing the matching graph tab.
- Review found reload and perspective edge cases. Reload normalizes identities
  without local graph evidence to List, and inventory inspection restores the
  identity perspective before focusing a node.
- Existing browser flows assumed Graph was the default after protection or
  lock remounts. They now explicitly select Graph where graph inspection is the
  tested behavior.
- One complete validation attempt was recycled after native BuildKit cache
  publication stalled; the unchanged exact head passed the replacement run.

## Decisions

- List is the default representation because it is the primary management
  surface. Graph remains available as progressive relationship detail.
- Identities without local relationship evidence cannot select Graph.
- The Rust/WASM identity projection and security boundaries remain unchanged.
