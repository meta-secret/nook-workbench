# Add Devices & access dashboard

## Outcome

Simple and Sentinel now expose an always-available **Devices & access** page
before vault creation, while locked, and while unlocked. It explains the
passkey or PIN/passphrase protecting the browser-local age identity, shows
non-secret passkey observations with explicit provenance, and relates that
identity to every locally known vault without moving vault-owned devices or
backup passwords into a global key store.

## Progress

- Added Rust-owned protection, identity, provider-observation, and verified
  vault-relationship models with migration-safe IndexedDB persistence.
- Added typed WASM request/snapshot classes so asynchronous IndexedDB access
  does not retain a recursive manager borrow.
- Added the responsive Svelte dashboard, permanent navigation, first-run nudge,
  English/Russian catalogs, provider labeling, progressive technical details,
  and locked/unlocked/no-vault states.
- Enabled TypeScript script preprocessing across every Svelte build surface so
  runtime enums are supported, and added preflight enforcement requiring enum
  members in named dashboard unions.
- Added Rust behavior tests, web unit tests, full Playwright flows, and a
  repository-owned UI demo.

## Decisions

- Browser-reported authenticator facts, Nook-verified vault relationships,
  user-supplied provider labels, and last-known locked metadata remain visibly
  distinct.
- WebAuthn provider names are never guessed; unknown remains an honest state.
- Backup passwords remain vault access methods, not device-key protection.
- Portable state, validation, identifiers, and closed vocabularies are owned by
  Rust or explicit TypeScript enums; Svelte remains presentation and browser
  lifecycle glue.
