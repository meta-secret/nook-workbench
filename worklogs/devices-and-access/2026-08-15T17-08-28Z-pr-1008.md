# Complete identity security epochs and browser recovery

## Outcome

Delivered the full security successor preserved during the semantic PR split.
Identity-held vault keys now advance through verified security epochs, remote
replicas reconcile without rollback, legacy password envelopes migrate safely,
and destructive browser recovery invalidates only the inaccessible local
installation while preserving encrypted vault data and peer identities.

## Progress

- Preserved the complete restored implementation on PR 1008 before reducing
  predecessor PR 1002 to its identity lifecycle and handoff foundation.
- Integrated merged PR 1002 and retained the security epoch, remote visibility,
  reconciliation, persistence, migration, recovery, and browser coverage.
- Added causal checkpoint ancestry validation, structural checkpoint
  quarantine, resumable rotation classification, and rollback-safe revocation.
- Added sequential non-epoch migration for multiple legacy password entries.
- Persisted verified remote epochs while locked before password enrollment.
- Zeroized plaintext key serialization during password envelope rewrap.
- Retired only the persisted inaccessible installation app ID during recovery.
- Adopted browser storage generations after successful and failed recovery.
- Updated Cortex architecture and product contracts for the delivered behavior.

## Implementation problems

- The original restored diff exceeded the preferred PR budget. The work was
  preserved first, then split by capability into linked PRs 1002 and 1008.
- Review found six security and recovery edge cases after the first exact-head
  validation dispatch. That run was stopped, every comment was fixed and
  replied to immediately, and validation was retriggered only after all threads
  were resolved.
- The browser suite exposed two new fixture defects: the password migration
  fixture had not activated vault crypto, and the recovery fixture had not
  persisted the app ID that recovery must retire. Both fixtures were corrected
  through the real production APIs; all 85 browser tests then passed.
- The first merge command completed the server-side squash but could not switch
  this worktree to `main` because another worktree owns that branch. Remote
  state confirmed the merge succeeded and the feature worktree stayed clean.

## Decisions

- Large work is split semantically by complete capability. Code, tests,
  migrations, and docs stay together; completed behavior is never deleted or
  compressed to fit a numeric PR limit.
- Verified epoch and reconciliation policy remains in Rust. TypeScript owns
  browser-exclusive locking and storage-generation lifecycle only.
- Legacy password entries migrate one at a time without rotating the security
  epoch. Epoch rotation remains blocked until every retained envelope supports
  key rewrap.
- Destructive recovery retires only the durable app ID of the inaccessible
  installation, never every identity member observed in the local directory.
