# Identity and vault architecture delivered

## Outcome

[Nook PR 912](https://github.com/meta-secret/nook/pull/912) was squash-merged.
It establishes the architecture for distributed virtual identities, their
installation-specific device keys, and identity-to-vault grants. It also adds
the Identity Bridge research interface with identity-first and vault-first
views, responsive graph layouts, shared canonical fixtures, and focused browser
tests.

## Progress

- Defined the distinction between virtual identities, physical devices,
  installations, device keys, sync providers, and vault grants.
- Specified separate installation-specific X25519 encryption and Ed25519
  signing keys, atomic pair rotation, epoch content keys, and recipient
  envelopes for active authorized installations.
- Made persisted zero-device identities invalid unless a recovery recipient
  remains, while keeping the zero-key state available only as an unpersisted
  setup draft.
- Specified vault-owned grants whose data-key envelopes target concrete active
  device keys rather than abstract identities or sync providers.
- Added the Identity Bridge research sketch using the shared graph component,
  with desktop and mobile layouts that preserve the identity-to-device and
  identity-to-vault relationships.
- Consolidated both browsing perspectives on one fixture, added accessible
  selectors and graph semantics, improved contrast, and added three responsive
  Playwright cases.
- Copied accepted identity sketches into Inspiration and removed rejected or
  contradictory experiments, including the active passkey-as-identity console.
- Addressed all review conversations across cryptographic semantics, bootstrap
  invariants, grant ownership, research isolation, accessibility, and fixture
  drift.

## Implementation problems

- Early research checks exposed formatting, dead-export, stale-import, and graph
  diagnostic issues; each was corrected before the final validation cycle.
- Browser-test output was briefly included in the change and then removed and
  ignored before merge.
- A failed-job rerun could not consume a prior-attempt build artifact. A fresh
  exact-head validation run completed successfully instead.

## Decisions

- An identity is virtual and distributed; hardware proves where it can act,
  while a vault grant determines what it may open.
- Each installation owns a distinct encryption/signing key pair. Adding an
  identity device does not implicitly grant that device access to existing
  vaults.
- Identity and vault browsing are complementary perspectives over one canonical
  relationship model, not separate sources of truth.
- Research packages remain isolated from production bundles. English-only
  experiment copy is permitted there, while any production port must use the
  shared translation catalogs.
