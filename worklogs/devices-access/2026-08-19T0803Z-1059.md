# Access canvas width and protector list

## Outcome

Devices & access now uses a wider shell than the secrets workspace. Identity versus Vault sits above Graph and List. List shows the passkey, PIN, or companion session that unwraps this browser's app key, and it no longer shows a sibling App key card in that 1:1 case.

## Progress

- Widened the app shell while Access is open, including login `/devices-access`.
- Collapsed browse chrome into a top Identity/Vault control and removed the duplicate identity row.
- List now returns after the first protector card. Graph and inspect still expose the app-key node.
- Spec, English/Russian lede, unit, e2e, and demo coverage were updated with the layout.

## Implementation problems

- The first host format waited on a cold Docker bake. The second pre-push reused cache.
- Opening Access from login only changed the path, so the shell stayed narrow until login applied the workspace route.
- Codex local and Cloud review were unavailable due to usage limits. Bugbot is not enabled. Delivery continued after repository-owned checks and `task pr:ready`.

## Decisions

- Graph remains the default layout and still shows the app-key relationship.
- List hides the app-key card only when a protector already unwraps that key.
- Vault chips remain under Vault browse because more than one vault can exist.
- Secrets workspace keeps `max-w-5xl`.
