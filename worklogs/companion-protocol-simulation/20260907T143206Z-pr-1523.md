# Companion identity browser adapters

## Outcome

PR #1523 delivered and merged the production paired-vault identity discovery
and encrypted handoff adapters. Browser channels now transport generated Rust
DTOs, while Rust owns admission, correlation, expiry, authorization, replay
protection, sealing, and website completion.

## Progress

- Added strict Rust status admission that binds the original discovery,
  current observation time, request identifier, vault identifier, and complete
  status shape into one admitted transaction.
- Added a stateful extension endpoint that retains issued discovery state and
  consumes every authorization attempt before validation or effects.
- Routed the website through its existing application WASM instance and kept
  the extension on companion WASM, avoiding a second production website WASM
  bundle.
- Replaced TypeScript pending-state and protocol decisions with generated DTOs
  and direct Rust calls.
- Extended direct dual-WASM composition coverage for malformed, unrelated,
  stale, concurrent, app-mismatched, replayed, and forged messages.
- Updated Chrome transport simulations to supply current generated DTOs while
  executing real Rust admission and application behavior.

## Implementation problems

- Security inspection found that the first adapter revision did not bind the
  entire discovery observation or recheck current endpoint presence during
  authorization. The protocol was strengthened before delivery, including
  one-shot consumption on every authorization attempt.
- The first website integration imported companion WASM beside application
  WASM. The Web isolation gate exposed the duplicate runtime, so the same Rust
  admission functions were exported through application WASM instead.
- Hosted Web and Dylint runs exposed test-only Rust helpers, raw TypeScript
  object arguments, const-member type syntax, and fixtures still returning the
  retired envelope. Each failure was corrected without adding application
  mocks or weakening a validator.
- `main` advanced twice during delivery. Both base changes were merged and all
  exact-head static, security, hosted, deployment, and readiness evidence was
  regenerated.

## Decisions

- Browser messaging remains infrastructure only; it cannot classify protocol
  state or authorize domain transitions.
- Website and extension WASM instances exchange generated structural DTOs,
  never cross-memory WASM handles.
- Browser test doubles are named and scoped as transport simulations. Rust
  endpoints, managers, protocol admission, and storage behavior use real
  production instances.
- The coherent adapter migration remained one PR despite the repository
  warning at 1,710 authored additions. Pairing approval, interactive unlock,
  and event-log protocols remain separate sequential PRs by domain boundary.
