# Deliver companion pairing event-authority preparation

## Outcome

PR #1552 delivered and merged a side-effect-free Rust/WASM preparation boundary.
It consumes a real prevalidated pairing approval and typed external event log,
validates the complete Simple-vault event authority, and returns an opaque
prepared capability. It performs no storage, browser, acknowledgement, or live
authority effect.

## Progress

- Nested activation beneath the pairing owner so admitted binding and retained
  authority fields remain private.
- Added exact event ID/bytes, vault, graph, authorization, projection,
  installation-key, envelope, and membership validation.
- Added a shared event-log architecture predicate covering explicit Sentinel
  operations and checkpoint-carried reserved Sentinel records; reused it for
  graph classification and self-enrolment authorization.
- Preserved typed `EventId` heads and eleven private failure kinds while
  intentionally exposing one generic WASM rejection.
- Added eleven exact real-instance Rust failure cases plus valid preparation,
  signed checkpoint/revocation/quarantine coverage, and generated WASM success,
  lifecycle, and rejection coverage without mocks.

## Implementation problems

- The initial PR combined preparation, candidate schema, IndexedDB persistence,
  replay, and load. As it approached 2,000 authored additions, implementation
  began optimizing around line count. The user stopped that approach. The full
  draft was preserved locally and PR #1552 was reconstructed cleanly around the
  independently useful preparation capability.
- Repeated review batches found real domain-boundary gaps sequentially:
  primitive graph heads, incomplete failure evidence, broad typestate
  visibility, Sentinel history hidden in epoch checkpoints, and untyped fixture
  timestamps. Each was fixed at its Rust owner with real behavior tests.
- Hosted checks found stale private-field assertions, native tests crossing the
  `JsError` boundary, an invalid store-ID fixture, and a 114-line test. These
  were corrected with typed internal operations, valid domain data, and a named
  checkpoint-history fixture.
- One mistyped local command accidentally started the default Docker build. It
  was interrupted after about 30 seconds during dependency compilation and
  made no source change.

## Decisions

- PR limits trigger functional scope design; they must never drive unrelated
  deletion or compressed implementation.
- Preparation ends at an opaque proof and conveys no persistent or live vault
  authority. Candidate storage and reader adoption remain serial successors.
- Historical architecture evidence is immutable operation history, including
  reserved checkpoint records; current materialized maps are not sufficient.
- Native Rust tests own the exhaustive private taxonomy. Generated TypeScript
  exercises only the generated public boundary and stable generic rejection.
- The preserved storage draft is reference material only. The next PR starts
  from merged `main` and reintroduces only its focused candidate-storage scope.
