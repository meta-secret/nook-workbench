# Companion protocol simulation framework

## Outcome

PR #1500 delivered and merged the typed Rust companion protocol and direct
real-instance simulation foundation.

## Progress

- Added canonical discovery, installation app-key, and encrypted identity
  handoff DTOs with typed admission and failure outcomes.
- Added real extension and website endpoint composition through the same
  authorize-and-seal operation exposed to production WASM.
- Added one-shot nonce consumption, exact discovery correlation, vault and
  app-key binding, and zeroized pending website state.
- Added native-safe internal errors so direct Rust scenarios do not construct
  WASM-only JavaScript errors.
- Added Development Core architecture for faithful infrastructure simulations
  and the independent-WASM structural DTO seam.

## Implementation problems

- Initial design separated authorization from real manager sealing. Security
  review required one Rust-owned operation and exact pending-request binding.
- Hosted validation found the companion WASM crate root above its source-size
  limit. A cohesive persistence export family moved into its own module.
- Hosted Rust and WASM lints found raw numeric construction, enum sizing,
  redundant exports, stale fixtures, and JavaScript-only native error paths.
  Each was corrected without suppressing production findings or weakening the
  generated ABI.

## Decisions

- Application behavior uses concrete objects and direct calls, not mocks.
- External browser or storage boundaries may use faithful alternate
  implementations and are called simulations.
- Structural Tsify DTOs cross independent WASM memories. WASM object handles
  do not.
- A nonce remains consumed after an authorized sealing attempt. Ambiguous
  failure requires fresh discovery rather than reopening replay.
- Test composition, production adapters, and remaining protocol families land
  as sequential architectural slices.
