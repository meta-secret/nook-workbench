# Deliver side-effect-free companion pairing admission

## Outcome

PR #1546 delivered and merged a Rust-owned, one-shot companion pairing
admission protocol across `nook-companion-core`, `nook-companion-wasm`, and
`nook-wasm`. The protocol validates an exact live request, installation and
vault identity, scope and provider manifest, and the recipient of already
sealed provider credentials. It returns opaque Rust capabilities and performs
no durable grant, event, provider, pairing-state, or acknowledgement effect.

## Progress

- Added typed request, observation, website authorization, approval, failure,
  and consuming authority state in Rust.
- Exposed generated companion-WASM and nook-WASM boundaries without moving
  browser-independent policy into TypeScript.
- Added native real-instance coverage, manager-bound nook-WASM coverage, and a
  dual-WASM TypeScript composition test that exchanges structural DTOs without
  browser messaging.
- Added eight manager-pairing tests and strengthened the endpoint test, giving
  18 cases across success, one-shot consumption, manager/vault/name/identity,
  signing and installation keys, provider scope, manifest substitution, and
  exact sealed recipient.

## Implementation problems

- Security rejected the initial effectful draft because fallible writes across
  independent stores could expose active authority before a later rejection.
  The slice was corrected to end at side-effect-free opaque admission; atomic
  durable activation is tracked separately.
- Dylint found fallible calls after mutating one-shot state. Website endpoints
  now consume themselves, and extension callers explicitly take and consume
  the authority before approval admission.
- Hosted host compilation required explicit `JsError` conversion in a native
  test, and Web verification found an unused TypeScript type import.
- The composition fixture invented a vault name, then incorrectly assumed the
  genesis fallback label named the live manager. It now names the real manager
  through the public operation and derives every DTO field from manager state.
- All 329 existing nook-WASM tests passed while measured package coverage fell
  to 80.65% against the existing 81.0% floor. Behavior-focused tests raised
  real boundary coverage; the floor and exclusions were not changed.

## Decisions

- Browser-independent pairing policy remains entirely Rust-owned; TypeScript
  only composes generated typed boundaries and structural DTOs.
- Opaque admission capabilities expose no getters or serialization and cannot
  themselves commit durable activation.
- Already sealed credentials are authenticated for the exact retained device;
  plaintext provider snapshots are never cloned for approval projection.
- Durable event import, grant/provider publication, pairing state, and accepted
  acknowledgement belong to the dependent atomic activation slice.
- Coverage regressions are repaired with real-instance behavioral tests, not
  threshold changes or mocks.
