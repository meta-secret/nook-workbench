# Direct Rust and WASM crate composition tests

## Outcome

PR #1534 merged a test-only Rust package that composes `nook-auth2`,
`nook-core`, `nook-companion-core`, `nook-wasm`, and
`nook-companion-wasm` directly without browser transport or application mocks.

## Progress

- Added 22 real-instance success and rejection tests across the crate graph.
- Exposed three existing typed companion operations from the `nook-wasm` crate
  root for native Rust composition.
- Added the package to the existing hosted native test and Docker source paths.
- Preserved the prior unfinished pairing protocol separately instead of
  carrying it into this pull request.

## Implementation problems

- The first hosted compile proved that three existing WASM companion operations
  were not reachable from native Rust. Narrow re-exports resolved the boundary.
- Repository policy required the harness to be explicitly classified outside
  product coverage and required `anyhow`-using tests to live under `tests/`.
- The Docker formatter initially inherited an empty dependency placeholder;
  copying the real harness into the existing source overlay resolved it.

## Decisions

- The harness has dev-only dependencies and no production dependency edge
  between WASM crates.
- Tests use production structs, managers, endpoints, and typed outcomes. No
  application mock or browser-channel imitation was introduced.
- Browser-backed manager completion remains a documented private boundary.
- No task-start plan was published for this slice because it began as an
  explicit strategy correction during active delivery; this worklog records
  that process violation rather than fabricating a retroactive plan.

## Validation

- `task loom:pre-push PR=1534` passed at the final head.
- Security passed the final exact head.
- Repository policy, Native Rust, WASM build and Node tests, Rust ecosystem,
  Web verification, Hive verification, coverage, and preview checks passed.
- `task pr:ready PR=1534` returned ready with no reasons.
- PR #1534 squash-merged as `1f18dc099de974fc623533226b62b47eaf3a9bf9`.

- TypeScript and browser-transport simulation are separate future capabilities.
- Pairing, unlock, and event-log behavior migrations require independently
