# Companion protocol composition tests

## Outcome

PR #1508 delivered and merged direct real-instance companion protocol tests in
Rust plus an independent dual-WASM TypeScript composition suite with no browser
transport.

## Progress

- Added behavior-focused Rust scenarios for discovery, correlation, expiry,
  app-key binding, revoked access, replay, sealing failure, and pending-state
  cleanup.
- Added a TypeScript suite that initializes companion-WASM and vault-WASM
  independently and transfers only generated structural DTOs between them.
- Exercised real `NookVaultManager` provisioning and persistence through a
  fresh in-memory IndexedDB implementation.
- Kept Chrome runtime and window messaging entirely outside the application
  behavior tests.

## Implementation problems

- The first hosted revision used a broad browser-data cleanup operation that
  reached unrelated browser stores. It was replaced by a fresh per-suite
  IndexedDB factory.
- Web-sys performs WebIDL brand checks. Bun resolved `fake-indexeddb/auto` and
  named package exports through distinct constructor identities, first failing
  `IDBFactory` admission and then `IDBOpenDBRequest` admission. The final suite
  installs and restores one coherent constructor/object graph for the complete
  IndexedDB runtime.
- Rapid `main` movement required current-base refreshes and repeated exact-head
  validation; no coverage floor or production invariant was weakened.

## Decisions

- Application tests compose production Rust endpoints and managers directly;
  there are no application-layer mocks or test-only protocol paths.
- Independent WASM memories exchange generated DTOs through structural clone,
  never cross-memory WASM object handles.
- The in-memory database is a faithful infrastructure implementation, isolated
  per suite and restored afterward.
- Production Chrome/window adapter migration remains a separate sequential PR.
