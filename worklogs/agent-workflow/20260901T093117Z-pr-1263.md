# Standardize agent activity and real delegation

## Outcome

Delivered and squash-merged the canonical activity and delegation contract. Every user-visible Gizmo, Team Agent, subagent, and skill action now uses `HH:mm:(PR):ACTOR:ACTION -> message`, with exact pull-request context, compact team actors, explicit commands, concrete wait targets, elapsed time, and observable state. Gizmo Prime must delegate every worker-executable task to a real active-harness Team Agent and stop instead of taking over when dispatch cannot produce an accepted handoff.

## Progress

- Replaced repeated metadata blocks with one compact activity line carrying the exact pull-request token.
- Closed the actor vocabulary to Gizmo Prime, routed team actors, and skill execution without personal agent names or repeated role labels.
- Required every wait to name the exact Task command or linked GitHub run or job.
- Removed standalone GitHub review waiting; complete validation dispatches first and review accumulates concurrently with checks.
- Removed transition-marker creation, parsing, backfill, and waiting. Legacy automated boundary comments are deleted before current feedback classification.
- Required all actionable pull-request comments to be addressed and resolved before readiness.
- Enforced real Team Agent delegation and fail-closed Gizmo behavior for worker creation, dispatch, startup, retry exhaustion, and handoff failure.
- Split an oversized preflight test module and documented the marker-free obsolete-validation workflow.
- Published the immutable schema-v4 agent statistics record.

## Implementation problems

- The requested presentation evolved materially from grouped YAML metadata to the final compact single-line contract. The immutable task plan remains the initial snapshot; the merged contract and this completion record capture the selected final format.
- Automated review produced 18 finding batches across 35 observed delivery heads. Findings exposed actor-mapping gaps, cancellation propagation gaps, obsolete-comment handling, oversized test structure, and review-state edge cases; each was routed to its functional owner and resolved before merge.
- Repeated validation cycles consumed substantial hosted time while the review lifecycle was being redesigned. The merged workflow removes the separate review wait and batches review findings with check failures.
- Post-merge statistics assembly exceeded Node's default subprocess output capacity. The emergent bounded repair was delivered separately in PR 1274 before statistics publication.

## Decisions

- The final activity schema is plain text, not a YAML block: `HH:mm:(PR):ACTOR:ACTION -> message`.
- The actor is the compact team type, never a personal agent name or the words `Team Agent`.
- Review is never a separate stabilization wait. Checks dispatch immediately; accumulated review and check results are handled together.
- Pull-request comments are addressed and resolved directly. No marker protocol participates in review readiness.
- Gizmo Prime owns integration and delivery state but is prohibited from performing Team Agent implementation or review-fix work.
