# Bound GitHub API output for agent statistics

## Outcome

Delivered and squash-merged a focused Loom repair that captures complete agent-statistics GitHub API responses up to a fixed 16 MiB ceiling and fails closed above it. The policy is available only through the closed `CommandOutputPolicy.GitHubApi` enum and is selected only by the agent-statistics GitHub adapter.

## Progress

- Replaced the platform-default subprocess capacity with a closed GitHub API output policy.
- Kept default subprocess callers unchanged.
- Used two immutable, statically analyzable subprocess option objects so provider capability and reachability audits remain intact.
- Added focused coverage proving complete 2 MiB capture and observable failure at 17 MiB.
- Used the landed repair to publish both PR 1263 and PR 1274 agent-statistics records.

## Implementation problems

- The first implementation used an options-object spread, which the hosted TypeScript subprocess capability audit correctly rejected.
- Replacing the spread with mutation passed that audit but made subprocess discovery conservatively classify the shared runner as an unresolved provider dependency.
- The final closed-enum design removed arbitrary caller-selected bounds and restored both static capability and provider-reachability proofs without adding exceptions.
- Agentic-AI-only paths intentionally skip the product PR workflow, while the repository ruleset still requires a product preview deployment. After exact-head readiness passed, the established admin squash path was required because no applicable preview deployment could exist.

## Decisions

- Callers cannot supply arbitrary byte counts; only the closed GitHub API policy receives the 16 MiB limit.
- Responses are never truncated. Below-bound output is complete, and above-bound output is an observable failure.
- Static subprocess capability and provider-reachability audits remain unchanged and fail closed.
