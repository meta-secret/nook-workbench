# Static deterministic agent workflows delivered

## Outcome

Merged a separate static TypeScript agent-workflow engine into Loom. The first reviewed workflow performs full Cortex evidence collection with five explicit lanes, an all-completed join, typed synthesis, and parent-owned lifecycle records.

## Progress

- Added a separate `loom-agent-workflow` command while preserving the existing Loom YAML leaf-tool command.
- Added compile-time workflow definitions, validation, scheduling, Codex SDK execution, structured-result decoding, journaling, projections, and terminal-reference replay inspection.
- Added one fresh read-only Codex thread for each reached agent task attempt.
- Added exact source and clean-worktree checks before and after every agent attempt.
- Reused the existing mechanical Cortex audit as a deterministic leaf.
- Updated Cortex with mandatory delegation criteria, static-topology rules, and the local Loom versus durable Hive authority boundary.
- Completed an exact-commit five-lane workflow run and reconciled its results through a typed synthesis node.

## Implementation problems

- The initial design/product/skills lane was broader than the documented partition policy. It was split into separate design/product and skills/entry-point workers.
- Source stability was initially checked only at workflow start. Before/after attempt checks now fail closed on HEAD, tracked-file, or untracked-file drift.
- Hosted validation found one use of an `undefined` guard that violated Nook's explicit-state policy. The guard was replaced, the hosted preflight was reproduced locally, and complete validation was rerun on the replacement head.
- The merge command succeeded remotely but local branch cleanup could not switch to `main` because another worktree owns it. A follow-up query confirmed the merge.

## Decisions

- Static graph topology is reviewed TypeScript. Runtime graph generation and YAML topology are prohibited.
- Loom is the current local scheduler. Hive integration must materialize static nodes as Hive tasks rather than running a second scheduler inside a Pod.
- Local event journals are authoritative for local runs only. Neo4j remains the durable authority in Hive mode.
- Workers are read-only in this first slice. The delivery owner retains integration, GitHub, Workbench, and merge authority.
- Lace is not used by this path.
