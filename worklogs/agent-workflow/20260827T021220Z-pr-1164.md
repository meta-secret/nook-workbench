# Deliver hierarchical Cortex and AI-team routing

## Outcome

Nook Cortex now routes knowledge through four explicit teams and one shared
authority. The AI team owns Cortex governance, Loom, agent skills, expert
registries, and AI delivery workflows. Agents load one owning team graph and
only the documents needed for their bounded task.

## Progress

- Moved AI, development core, SRE, and web development under `.cortex/teams`.
- Moved genuinely cross-team architecture, product indexes, references, and
  dynamic skills under `.cortex/shared`.
- Replaced exhaustive heading maps with concise, categorized document maps.
- Updated executable skills, prompts, expert configurations, source callers,
  and Loom path contracts for the new ownership model.
- Added mechanical checks for graph ownership, duplicate links, root routing,
  foreign-team entries, and selective context loading.

## Implementation problems

- Compacting the root agent contract initially removed phrases enforced by
  repository-policy tests. Restored the no-Python severity, feature ownership,
  1,000-line decomposition, test-boundary, and self-improvement routing
  invariants without duplicating their full owner documents.
- A documentation-link edit in a web source comment activated the UI demo
  contract. The non-behavioral comment change was removed so this documentation
  migration did not claim a UI behavior change.

## Decisions

- Use `shared` as the concise common-knowledge parent.
- Keep the root knowledge graph as a router only.
- Index every Cortex document exactly once in its owner graph.
- Keep section navigation inside document headings instead of knowledge-graph
  anchor chains.
- Route cross-team dependencies through one delivery owner; team agents stop at
  foreign ownership boundaries.
