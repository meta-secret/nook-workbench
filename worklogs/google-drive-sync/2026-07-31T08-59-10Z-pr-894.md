# Fix Google Drive Connect event parse failure

## Outcome

Merged https://github.com/meta-secret/nook/pull/894. Google Drive Connect & sync
no longer fails solely because same-name appData event files include unreadable
junk; outbox flush recovers by publishing good local bytes.

## Progress

- Drive fetch skips unreadable/wrong-id candidates and treats all-unreadable
  names as absent.
- Outbox flush always put-if-absent and removes pending rows only after success.
- ParseRemoteEvent/ParseStoredEvent Display includes the inner parse reason.
- Added Rust regression tests for candidate selection and error Display.
- Updated vault-event-log design note for Drive duplicate semantics.

## Implementation problems

- Contested primary checkout kept switching to an iCloud branch and stashing
  this work; finished in an isolated git worktree.
- First `task format` failed on clippy needless_continue; rewritten to
  `if let Some`.

## Decisions

- Unreadable same-name Drive candidates are non-events (skip), matching the
  duplicate-tolerance design rather than hard-failing assess/connect.
- Listed remote names alone are not proof an event is present for outbox skip.
