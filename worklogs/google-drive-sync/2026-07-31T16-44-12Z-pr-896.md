# Fix Google Drive Connect assess timeout

## Outcome

Merged https://github.com/meta-secret/nook/pull/896. Google Drive Connect & sync
no longer hangs until the 30s assess timeout on already-synced vaults, and the
timeout toast no longer mentions a PAT.

## Progress

- Drive list requires matching `appProperties.event_id` for listed digests.
- Provider sync and writable-store guard fetch only missing remote event ids.
- Shared `toasts.error_timeout` locale is provider-agnostic (en/ru).
- Connect races use `startVaultDiscoveryTimeout` with that locale key.
- Added UI demo covering the demo-origin Google gate and timeout copy.

## Implementation problems

- First Verify failed: UI paths changed without a demo commit (contract only
  sees HEAD, not the working tree).
- Second Verify failed: UI demo used full Google OAuth helpers, but demos run on
  `127.0.0.1:5183` which is outside authorized Google origins.

## Decisions

- Prefer skipping already-local remote ids over raising the 30s timeout.
- Keep UI demos on the origin gate for Google Drive, matching iCloud demos, and
  assert timeout copy via `vault.t('toasts.error_timeout')`.
