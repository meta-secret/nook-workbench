# Extract nook-core sync unit tests into focused modules

## Outcome

Squash-merged Nook PR 825. The sync provider-store and validation production
modules now delegate their unit-test bodies to dedicated test modules. All four
touched Rust files are below the 1,500-line source-file ceiling, with no
behavioral or public API change.

## Progress

- Moved 32 provider-store unit tests into `sync_provider_store_tests.rs`.
- Moved 32 sync-validation unit tests into `validation_tests.rs`.
- Preserved the existing private-module test paths and access to implementation
  details through the parent module.
- Rebasing the focused branch onto the latest `main` also exercised the
  independent Rust coverage workflow delivered in PR 826.

## Implementation problems

- The original validation cycle was canceled when the source-size delivery was
  paused for the urgent PR preview-latency repair.
- After that repair merged, the branch required a base update and a fresh
  exact-head validation cycle.
- The repository-wide formatting wrapper still prepared unrelated web and Hive
  formatter surfaces for this Rust-only extraction.

## Decisions

- Keep unit tests adjacent to their owning modules as private `#[cfg(test)]`
  submodules rather than converting them into public integration tests.
- Treat Rust test files as source files subject to the 1,500-line ceiling.
- Preserve test behavior exactly; this PR is structural extraction rather than
  a domain-logic rewrite.
