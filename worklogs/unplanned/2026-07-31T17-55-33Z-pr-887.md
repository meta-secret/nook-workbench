# Keep authorized signing seed on extension handoff

## Outcome

Merged https://github.com/meta-secret/nook/pull/887. Extension identity handoff
keeps the durable authorized signing seed when the vault event log already has
events, so Approve no longer appends JoinApproved as an unauthorized actor after
a reinstall-style handoff.

## Progress

- Added `choose_signing_seed_after_identity_handoff` in nook-core with keep-stored
  vs adopt-handoff policy and unit coverage.
- Wired WASM device_protection / event_log seed selection to that policy.
- Unblocked post-#886 extension CI: companion WASM load for classic content
  scripts, service-worker import graph, Pilot mounting, and local e2e Sentinel
  URL fallback.
- Fixed file-sync e2e listings to include `appProperties.event_id` required by #896.

## Implementation problems

- Companion WASM init in content scripts hit classic-script parse failures
  (`import.meta`, top-level await) and unit-test races after removing TLA.
- Extension smoke failed on local Playwright Simple Vault (`127.0.0.1:5174`)
  which has no paired Sentinel origin.
- Browser e2e inherited a main #896 stub gap: Drive-shaped list filtering ignored
  digest-only `.yaml` names from the file-sync stub.

## Decisions

- Prefer stored authorized signer whenever the event log has events; persist
  handoff seed only for empty-log create or missing local seed.
- Embed companion WASM bytes into content bundles and strip wasm-bindgen
  `import.meta.url` fallbacks at build time.
- Keep Pilot-off-Sentinel e2e assertion via production Sentinel host when local
  Simple Vault has no pair.
