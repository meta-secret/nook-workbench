# Restore portable hosted WASM dependency cache reuse

## Outcome

Hosted WASM dependency layers are now reusable across separate GitHub Actions
builders and runs. The manifest-only producer extends its digest-pinned Rust
base inside one Dockerfile, Main rejects incomplete publications with an
isolated fresh-builder assertion, and a source-only pull request independently
proved first-solve reuse.

## Progress

- Traced the repeated rebuilds through the immutable dependency scope, outer
  WASM consumers, and named BuildKit target contexts.
- Added the fingerprinted scope directly to source/export consumers in Nook PR
  812, then rejected that partial repair after a fresh hosted proof still
  rebuilt every expensive dependency stage.
- Moved manifest-only dependency producers beside their digest-pinned Rust base
  in one Dockerfile.
- Added a mandatory Main fresh-builder cache assertion and focused preflight
  invariants.
- Passed exact-head validation, addressed review, squash-merged Nook PR 816,
  and completed Main plus source-only hosted proof.

## Implementation problems

Nook PR 812 added the immutable dependency-fingerprinted scope directly to
outer WASM consumers. That change was necessary but insufficient. Controlled
proof PR 815 preserved the dependency fingerprint and invalidated only Rust
source; its first hosted solve still executed cargo-chef release, cargo-chef
clippy, and WASM release-test dependency compilation.

The producer reached `rust-base` through a Bake named target. Its exported
records were reusable later inside one BuildKit daemon but did not retain a
portable parent identity across fresh hosted builders.

The initial PR 816 run also exposed one preflight rustfmt gap. The exact
mechanical formatting fix, focused preflight suites, and repository formatter
all passed before the corrected head was pushed.

## Decisions

- Keep manifest-only Rust dependency targets beside `rust-base` in
  `nook-app/docker/base.Dockerfile`.
- Remove the named `rust-base` target context from native and WASM dependency
  producers.
- Require a Main publication assertion that creates a new Docker-container
  builder, imports only the exact fingerprinted scope, and requires the three
  expensive dependency steps to be `CACHED`.
- Keep pull requests read-only cache consumers and accept a one-time trusted
  cold seed only when the dependency fingerprint changes.
