# Accelerate isolated remote tasks

## Outcome

Reduced the high-frequency hosted remote tasks from roughly 9–19 minutes to
roughly 3–4 minutes while preserving ephemeral GitHub-hosted execution and
read-only reuse of the trusted Main cache.

## Progress

- Measured queue, setup, and task execution separately on recent remote runs.
- Added narrow source-sealed build graphs for Rust tests and web artifacts.
- Routed `rust:test`, `web:check`, `web:test`, and `extension:check` through the
  focused graphs without changing the remaining remote task catalog.
- Added repository invariants for hosted placement, cache policy, task routing,
  and the focused Docker/Bake topology.

## Implementation problems

- The original persistent-runner experiment was fast but allowed
  branch-controlled Taskfiles and Docker commands to reach a persistent host
  daemon. It was fully replaced before merge with isolated hosted execution.
- Writing branch-scoped GitHub Actions caches would have competed with the
  existing Main cache near the repository cache quota, so branch jobs remain
  read-only consumers.

## Decisions

- Keep untrusted branch tasks on ephemeral GitHub-hosted runners.
- Reuse only the trusted Main cache and make the workload graph narrower rather
  than expanding cache writes.
- Preserve full validation semantics; optimize focused developer tasks only.

## Validation

- `rust:test`: 3m17 end to end, down from roughly 9 minutes.
- `web:check`: 3m41, down from roughly 15–19 minutes.
- `web:test`: 3m45.
- `extension:check`: 3m50, down from roughly 18 minutes.
- Exact-head PR run 30512009709 and Rust ecosystem run 30512009542 succeeded.
- `task pr:ready PR=878` passed and Nook PR 878 was squash-merged.
