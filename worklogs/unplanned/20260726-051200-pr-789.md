# Repair Main BuildKit cache publishing latency

## Outcome

Removed the dedicated Main cache reconstruction job and moved validation-gated,
serialized cache publication into the native, WASM, and web producers that
already own the solved BuildKit graphs.

## Progress

- Traced the reported 17-minute job to a fresh builder that repeated Rust,
  cargo-chef, WASM, and web graph solves before exporting.
- Added producer-local publishers that verify read-only and then export from
  the same warm job-scoped builder.
- Serialized native, WASM, and web uploads to avoid Actions cache throttling.
- Preserved the isolated no-import, forced-zstd WASM dependency export.
- Added repository invariants and updated CI architecture documentation.

## Implementation problems

- Automated review identified three cache-integrity risks in the first design:
  early WASM publication, concurrent uploads, and loss of the hardened WASM
  dependency export path. The implementation was revised before merge.
- One exact-head run caught Rust formatting drift in the preflight invariant;
  it was corrected and the replacement run passed.

## Decisions

- Shared cache scopes are published only after their owning validation lane
  succeeds.
- Main cache writers are serialized native to WASM to web; browser consumers
  remain read-only and parallel after the WASM handoff.
- Cache publication is a local export of solved graphs, not an independent
  reconstruction workflow.
