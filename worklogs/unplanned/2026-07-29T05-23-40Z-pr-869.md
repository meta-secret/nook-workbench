# Work summary

## Outcome

Made GitHub-hosted runners the primary execution environment for Nook agent
validation. Agents can repeatedly dispatch one allowlisted task with
`task remote TASK_NAME=<name>`, while full pull-request validation runs only
after an explicit validation-label request and remains mandatory for merge.

## Progress

- Added a 17-task hosted execution catalog with one GitHub Actions job per
  task, all on GitHub-hosted Ubuntu runners.
- Added exact-branch and exact-head guards to remote task dispatch and
  pull-request validation requests.
- Changed the PR workflow so pushes do not start the product pipeline;
  `ci:validate` requests the normal suite and `ci:full-e2e` requests and
  preserves the complete browser suite.
- Added remote Playwright artifact bindings and unconditional diagnostic
  uploads for browser tasks.
- Updated the canonical Cortex workflow, repository instructions, agent
  prompts, skills, and README to make hosted remote execution the default.
- Addressed every actionable review thread, passed exact-head readiness,
  squash-merged Nook PR 869, and removed the temporary production-smoke branch.

## Implementation problems

- The first hosted validation exposed an obsolete preflight contract that still
  expected push-triggered PR checks. The contract was updated to assert the new
  label-gated behavior.
- Review found that an unrelated label could otherwise create an all-skipped
  successful workflow, that a normal request could weaken a persistent
  full-E2E request, and that remote browser diagnostics were trapped inside
  containers. A mandatory label guard, full-label-set evaluation, host artifact
  mounts, and unconditional uploads closed all three gaps.
- GitHub deleted the merged feature branch before the production smoke. The
  remote dispatcher correctly refused the missing branch, so a temporary branch
  from merged Main was used for the smoke and deleted afterward.

## Decisions

- Use labels on the existing PR instead of separate experiment branches for
  full validation.
- Treat `ci:full-e2e` as sticky while it remains on the PR; a later normal
  request cannot downgrade it.
- Reject unrelated label events explicitly instead of accepting an all-skipped
  workflow.
- Keep remote execution allowlisted and read-only rather than accepting
  arbitrary shell text or repository secrets.
- Require a clean, pushed, non-Main branch for focused remote tasks and the
  exact PR head for full validation.
