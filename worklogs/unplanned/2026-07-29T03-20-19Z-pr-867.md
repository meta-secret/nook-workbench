# Work summary

## Outcome

Replaced the checked-in upstream Impeccable distribution with a pinned,
Docker-built and content-digest-verified dependency that Codex and isolated
workers materialize locally through Task.

## Progress

- Removed 127 vendored upstream files and ignored the generated replacement.
- Added a digest-pinned Docker image and Task targets for image construction,
  offline installation, verification, context loading, and detector hooks.
- Kept the Nook-specific Svelte and Rust/WASM taste skill as first-party source.
- Updated repository policy and hooks to use the containerized runtime.

## Implementation problems

- The upstream installer fetched a mutable payload at installation time even
  when the CLI version was pinned. Installation was moved into the image build,
  the complete generated tree was pinned by SHA-256, and runtime materialization
  was made network-disabled.
- The merge command completed the squash merge but could not switch this
  worktree to `main` because another worktree owns that branch. The merged PR
  and deleted remote feature branch were verified independently.

## Decisions

- Docker owns network access, versioning, and executable runtime behavior;
  Codex reads the generated skill from the bind-mounted checkout.
- Both the CLI version and generated skill digest must change deliberately
  during an upstream update.
- Generated Impeccable content is dependency output, never authored Nook source.
