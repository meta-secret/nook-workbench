# Complete vault facade decomposition

## Outcome

Converted the large Svelte vault implementation into a compatibility facade
over responsibility-focused reactive state and action modules. The root file
fell from 1,952 lines to 927 lines while preserving its flat component-facing
API; its remaining methods are computed presentation state, serialization
queues, or thin delegates.

## Progress

- Kept reactive fields in the existing runtime, UI, provider, session, secrets,
  Sentinel, and sync state slices.
- Moved architecture draft/application behavior into `vault/architecture.ts`.
- Moved unlocked-session cleanup and reset behavior into `vault/session.ts`.
- Moved settings, admin, help, and browser-data actions into `vault/ui.ts`.
- Moved initialization and device-identity orchestration into
  `vault/lifecycle.ts`.
- Moved vault switching into `vault/local-login.ts`, device locking into
  `vault/device-protection.ts`, and idle-session behavior into
  `vault/idle-session.ts`.
- Moved provider selection and persistence helpers into `vault/providers.ts`.
- Moved synchronization and event-outbox behavior into `vault/sync.ts`.
- Moved secret paging, decryption, and authenticator-code behavior into
  `vault/secrets.ts`.
- Added narrow provider, sync, architecture, session, and UI action contexts,
  so those modules depend on explicit state fields and capability ports instead
  of the complete facade.
- Kept `draftVaultType` typed and initialized with the Rust/WASM `VaultType`
  enum (`VaultType.Simple`) rather than a string literal.
- Pushed commit `1069fcbc` to `codex/vault-state-refactor` and updated Nook PR
  821 while intentionally leaving it open and unmerged.

## Implementation problems

- The first focused check exposed stale imports left by the extractions and an
  overly narrow disposable-record helper type. Removing the imports and typing
  the helper by its `free()` capability restored a clean check without changing
  ownership behavior.
- The Workbench-wide validator remains blocked by unrelated pre-existing Hive
  records and an older unplanned record.

## Decisions

- Preserve the existing flat `VaultState` API in this pull request to avoid a
  component migration mixed with the responsibility split.
- Treat the remaining facade line count as compatibility surface, not retained
  workflow ownership.
- Apply dependency inversion progressively: the high-traffic provider and sync
  modules and all newly extracted modules use narrow contexts; older Sentinel,
  password-unlock, OAuth, and multi-device modules remain candidates for
  independent follow-up narrowing.

## Validation

- `task format` completed successfully.
- `.github/scripts/ui-demo-contract.sh "$(git rev-parse origin/main)"` passed
  and identified the existing large-vault search demo.
- `task web:check` passed for the unified, Simple, and Sentinel applications
  with zero errors and zero warnings.
- `task web:test` passed 30 test files and 235 tests.
- `git diff --check` passed.

## Remaining work

None for this pull request. Older Sentinel, password-unlock, OAuth, and
multi-device action modules can adopt similarly narrow contexts in independent
follow-up refactors.
