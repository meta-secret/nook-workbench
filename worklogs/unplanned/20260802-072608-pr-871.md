# Strengthen web quality and security checks

## Outcome

Squash-merged Nook PR 871. Nook's ordinary web validation now combines typed
promise and exhaustiveness linting, unsafe DOM sink detection, production
dependency audits, property-based security coverage, and sanitized landing-page
translation markup across the main web family and independently deployed
research package.

## Progress

- Rebuilt the stale, conflicted PR on current `main` and migrated the intended
  quality gates without reviving obsolete branch state.
- Added pinned `eslint-plugin-no-unsanitized` and `fast-check` dependencies,
  typed ESLint project coverage for app, shared, extension, scripts, and e2e
  sources, and high-severity production dependency audits.
- Replaced direct translated `innerHTML` assignment with a DOMPurify fragment
  allowlist that preserves only `br` and `code` markup with no attributes.
- Added property coverage proving persisted logs remove query and fragment
  secrets, plus extension regressions for unknown protection states and strict
  versus best-effort companion launcher failures.
- Extended the independent Web Research check path to audit its own lockfile.
- Added focused preflight ownership checks and split them into a cohesive source
  file to preserve the repository's 1,000-line source limit.
- Addressed every review finding with a visible targeted reply before resolving
  the conversation.

## Decisions

- Runtime messages are treated as untrusted boundary input even when their
  TypeScript transport shape is generated or generic; unknown protection states
  fail closed.
- Credential queries may return a structured locked result even when opening an
  auxiliary launcher fails, while paired-vault unlock requests propagate the
  launcher failure through their existing explicit error response.
- Optional fixture and YAML input is normalized before exhaustive switching so
  typed exhaustiveness and the no-authored-absence rule remain compatible.
- Dependency audits live in each independently installed package's CI check
  path rather than assuming one lockfile represents the entire web family.
