# Parallel UI demo and browser cache delivery

## Outcome

Delivered and squash-merged the PR workflow and cache changes. Headless UI demo
recording is no longer nested in web verification, and the browser image has a
dedicated post-success publisher for trusted Main and exact-head reuse.

## Progress

- Measured the reported workflow and separated package-layer cost from full-step cost.
- Added the sibling UI demo job and kept the required preview aggregator explicit.
- Added exact browser-cache probing, trusted fallback, and cache-only publication.
- Removed compiler-cache credentials from browser-only PR jobs.
- Added mechanical cache, workflow, and documentation consistency contracts.
- Addressed and resolved every actionable review thread.

## Implementation problems

- The first design allowed publication through a validation target. It was split into a read-only solve and dedicated cache-only publisher.
- Exact and Main browser importers could overlap. An exact-scope probe now selects the exact graph alone when present.
- Full-e2e and required-preview paths needed separate ownership and failure semantics. The workflow now publishes after successful full-e2e validation and always audits required preview dependencies.
- Focused preflight did not initially exercise a test Clippy rule. Panic-based section lookups were replaced with contextual propagated errors before complete validation.

## Decisions

- Preserve parallel long-running jobs; do not trade minutes of concurrency for seconds of shared setup.
- Publish shared browser graphs only from trusted Main after success.
- Publish PR retry graphs only after successful exact-head browser validation.
- Keep browser-only runners outside the SeaweedFS compiler-cache credential boundary.
