# SeaweedFS and Zot Rust cache repair

## Outcome

Squash-merged Nook PR 902. Hosted Rust builds now use private Zot cache images
for portable BuildKit layers and SeaweedFS for compiler objects. Remote branches
can publish only isolated branch/task Zot refs; Main remains the only publisher
of protected Main refs and authoritative SeaweedFS objects.

## Progress

- Removed GitHub Actions cache exporters from the Docker Bake graph.
- Added deterministic branch-first, Main-second Zot imports and branch-only
  Remote exports.
- Integrated separate SeaweedFS Main read/write and Remote read-only identities.
- Narrowed focused Rust build contexts and colocated dependency stages with their
  parent image so layer identities remain portable across fresh builders.
- Added stable BuildKit secret mounts whose values do not change cache keys.
- Added upgrade-safe SeaweedFS credential reconciliation and mechanical preflight
  coverage for isolation, permissions, restore order, and workflow wiring.
- Addressed all six review conversations and resolved them after replies were
  visible.

## Implementation problems

- The original focused graph still inherited a non-portable parent identity from
  a named context, so fresh workers missed cargo-chef layers despite cache import.
- Broad source copies and Docker metadata invalidated compile vertices until the
  focused Dockerfile received a narrow ignore contract.
- Registry extraction remained a meaningful part of total wall time after the
  Rust compile layer became cached; the remaining time is transfer and test
  execution rather than dependency compilation.
- Existing SeaweedFS credentials required a controlled service recreation before
  the new scoped identities could be proven live.

## Decisions

- Zot is the authoritative cross-worker BuildKit layer store; it is simpler and
  more portable than a separate GitHub Actions cache scope.
- SeaweedFS remains the compiler-object cache, with Main as the only writer and
  Remote jobs restricted to reads.
- New branch dependencies are persisted immediately as complete branch/task Zot
  layers; they do not require Remote write access to SeaweedFS.
- Pull-request cache exporters are disabled. Same-repository validation may use
  the ACL-limited Remote restore identity, while forks receive no credentials.
