# Explicit application state refactor

## Outcome

Delivered and squash-merged the repository-wide explicit-state refactor. Nook
now documents and statically enforces authored TypeScript/Svelte absence rules,
Rust panic/error constraints, enum ownership, typed JSON boundaries, and the
1,000-line source limit. Mutable application state uses named variants and
enums across the vault UI, extension, CI agent, and Rust/WASM boundaries.

## Progress

- Added the canonical `.cortex` guidance and syntax-aware preflight gates.
- Refactored implicit `undefined` and `null` application state into named
  lifecycle and domain states while preserving explicit external-boundary
  normalization.
- Migrated raw discriminant strings to enums and kept portable domain ownership
  in Rust/WASM.
- Tightened Rust policy for panic shortcuts, test `Result` propagation, and
  production `anyhow`.
- Split oversized source and test responsibilities to keep authored files below
  1,000 lines.
- Repaired enrollment, UI-demo, and CI-readiness behavior exposed by exact-head
  validation.

## Implementation problems

- The first broad migration left type errors and missed authored absence in
  delegated consumers. Repeated exact-head checks exposed these incrementally;
  the final implementation expanded the AST-backed scanners and completed the
  consumer inventory.
- Join enrollment successfully wrote the remote request but then required an
  active local vault while persisting provider state. The save path now branches
  on the explicit provider-store scope and preserves the unscoped enrollment
  provider until a vault exists.
- UI demos reused an E2E build with the short idle-session timeout, locking the
  large-vault demo. The demo build now carries its explicit human-paced timeout
  through the build fingerprint.
- The final readiness container compiled a CI-agent surface not covered by the
  product preview job and found remaining implicit API absence. Those values now
  normalize into explicit pagination, reviewed-commit, workflow-status, and
  conclusion states.

## Decisions

- `undefined` and `null` do not model authored application state; `void` remains
  TypeScript's intentional unit/effect type.
- `Option` remains valid for truthful Rust lookup, parser, input, cache, and
  compatibility absence, but named persisted/domain states use enums.
- UI and browser lifecycle mechanics remain TypeScript-owned; portable policy,
  identifiers, validation, and domain enums remain Rust/WASM-owned.
- Wire-format strings remain only at compatibility boundaries and are converted
  immediately to typed states.
