# Centralize Rust i18n in nook-app-common

## Outcome

Squash-merged Nook PR 903. The duplicated Rust i18n registries and catalog
implementations now have one dependency-light home in `nook-app-common`, shared
by `nook-auth2`, `nook-core`, the WASM/web generator, and extension packaging.

## Progress

- Added `nook-app-common` as a leaf crate with only `serde_json` as a dependency.
- Moved the canonical locale catalogs, translation implementation, tests, and
  generated Rust key registry into the common crate.
- Deleted the duplicate `nook-auth2` registry and retained compatibility
  reexports in `nook-core` for downstream callers.
- Updated generation, extension packaging, Docker, Task, coverage, workflow,
  source-hash, and architecture inputs to consume the common location.
- Added preflight enforcement for the leaf dependency boundary and the absence
  of the legacy registry and catalog paths.

## Decisions

- `nook-app-common` is a dependency-light leaf for genuinely shared portable
  application code, not a general dumping ground.
- Domain-specific behavior remains in its owning crate; common code must have
  multiple real consumers and must not introduce upward dependencies.
- Rust remains the source of truth for canonical translation keys and catalogs;
  generated TypeScript constants are boundary artifacts for UI callers.
