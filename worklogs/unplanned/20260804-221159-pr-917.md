# Ship persistent vault workspace URLs

## Outcome

Nook's Vault, Devices & access, Admin, Add device, Settings, and Help workspaces now have stable, bookmarkable URLs. Reload and browser back/forward restore the selected workspace, while URL state remains deliberately coarse and non-sensitive. The existing Svelte/Vite shell was sufficient, so no SvelteKit migration or new router dependency was needed.

## Decisions

- Keep route identity in a typed workspace-route module and browser lifecycle glue in the Svelte shell.
- Canonicalize recognized routes with `replaceState`, removing query and hash state rather than persisting search, identifiers, or editor state.
- Reuse one SPA-alias definition across unified, Simple, and Sentinel Vite builds, including assembled `/simple` and `/sentinel` preview paths.
- Disallow authenticated workspace routes in the generated public `robots.txt`.

## Problems encountered

- Two TypeScript boundary errors were exposed by hosted `web:check` runs and repaired before the final gate.
- An initial PR workflow hit transient BuildKit/WASM contention; unchanged functionality was revalidated on later exact heads.
- Local Docker formatting initially contended with another worktree's BuildKit activity; the required formatter was rerun to completion without unrelated changes.
- Codex review identified URL canonicalization, nested preview parsing, and crawler-exclusion gaps; all three were fixed, replied to, and resolved.
