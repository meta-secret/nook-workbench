# Work summary

## Outcome

Portable authentication observation limits and validation now live in Rust
behind typed WASM adapters. Chrome-specific sender authorization, listener
lifecycle, and browser dispatch remain in TypeScript. The extension service
worker was decomposed into cohesive routing modules, and every affected
authored source remains at or below 750 lines.

## Progress

- Added companion-core validation for observation batch and field-count
  bounds, with behavior-focused Rust coverage.
- Exposed the portable policy through both typed WASM boundaries while keeping
  structural transport narrowing in TypeScript.
- Extracted website operations, lifecycle routing, external companion routing,
  account selection, passkey operations, and session lifecycle ownership from
  the service-worker entrypoint.
- Centralized lifecycle and launcher protocol vocabulary and added focused
  extension routing, adapter, session, and demo coverage.

## Implementation problems

- Review found TypeScript slices and clamps that prevented Rust from observing
  invalid values. Those transformations were removed or raised only to a
  transport safety ceiling so portable Rust remains the policy authority.
- Review found optional launcher intent encoded as a property bag. The adapter
  now normalizes it into an explicit intent enum before routing.
- Main advanced before complete validation. The branch merged current Main,
  reran mandatory formatting and focused validation, then completed the full
  exact-head suite.
- One local Docker content-store race interrupted the first formatter retry.
  Repeating the unchanged host-apply command succeeded with populated caches.

## Decisions

- TypeScript owns Chrome trust, browser lifecycle, and structural transport
  narrowing; Rust owns reusable authentication policy and bounds.
- Boundary adapters must preserve rejected values for Rust rather than clamp
  them into the accepted domain.
- Protocol intent is represented explicitly instead of inferred from optional
  object properties.

## Validation

- Mandatory host-applied formatting and pre-push hygiene passed on the merged
  exact head.
- Hosted `preflight,extension:check` passed in Actions run 31591862718.
- Complete exact-head validation passed in Actions run 31592490738, including
  native Rust, WASM, Node, web, headless UI demo, fuzz, Dylint, Kani,
  dependency policy, RustSec, Proptest, Insta, Loom, and coverage gates.
- The readiness audit reported `ready: true` with zero unresolved threads and
  a successful exact-head deployment before squash merge.

## Remaining work

  subsequent focused PRs. Mobile application work remains excluded.
