# Extract extension enrollment outcome controller

## Outcome

Squash-merged Nook PR 842. The authentication enrollment content flow is now
857 lines, with evidence classification, observation lifecycle, staged-code
refill, and commit/reject/timeout behavior isolated in the 226-line
`enrollment-outcome.ts` controller.

## Progress

- Extracted DOM outcome evidence and typed classifier round-trips behind narrow
  commit, reject, and timeout callbacks.
- Preserved enrollment ceremony orchestration and rendering in the flow module.
- Strengthened the focused 2FA demo to prove the intermediate verification
  message and final saved state.
- Updated the shared demo Chrome stub to answer the current typed pairing-state
  query.

## Implementation problems

- The initial demo contract required focused visual evidence.
- The first demo execution exposed a race between Svelte bootstrap and
  `setContent()`.
- The next run exposed an obsolete storage-only pairing fixture.
- Review correctly required a real web origin instead of `about:blank`; the
  demo now starts from static same-origin `/terms.html`.

## Decisions

- Split by enrollment outcome responsibility, not arbitrary line ranges.
- Keep the demo on a real origin so origin-bound enrollment behavior remains
  representative.
- Preserve the incumbent compact Pilot UI and prove both pending verification
  and successful persistence.
