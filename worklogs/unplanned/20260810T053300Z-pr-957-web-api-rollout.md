# Complete Rust-owned web API discipline rollout

## Outcome

Completed the strict TypeScript API rollout and moved portable browser-extension
policy into companion Rust/WASM. Merged Nook PRs 957, 961, and 962. The final
Main revision is green.

## Progress

- Enforced one parameter per authored TypeScript function or method.
- Enforced named typed values instead of raw object call arguments.
- Prohibited authored `unknown` and generic value bags in domain and
  application APIs, with narrow transport adapters as explicit exceptions.
- Moved portable extension decisions, validation, protocol classification, and
  state policy behind typed companion Rust/WASM APIs.
- Kept TypeScript responsible for browser lifecycle, DOM, Chrome APIs, and
  presentation orchestration.
- Added Rust behavior coverage and web/extension regression coverage.
- Updated Cortex and mechanical preflight/ESLint enforcement.

## Implementation problems

- PR 961 repaired Svelte snippet rendering, structured log persistence, and
  stale string lookalikes for Rust/WASM enums.
- PR 962 repaired the remaining OTP enum fixture, restored structured device-id
  evidence through the serialized logging adapter, and aligned extension e2e
  fixtures with typed session and pairing ingress contracts.

## Decisions

- Use direct complete PR validation as the default because it runs the required
  gates in parallel. Reserve focused remote tasks for isolated diagnostics that
  are faster than the complete suite.
- After each push, review threads were inspected while validation ran. New
  actionable feedback preempted the obsolete run and was addressed before the
  next complete validation cycle.
- Treat serialized log context as a narrow adapter exception. Domain and
  application APIs continue to reject generic value bags.
