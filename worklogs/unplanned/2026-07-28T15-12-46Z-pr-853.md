## Outcome

Nook now treats source structure as its most critical P1 code-architecture invariant:

- authored non-Rust source must stay at or below 1,000 lines
- authored Rust source must stay at or below 1,500 lines
- separate Rust unit-test files under `src` are prohibited
- crate-level `tests/` remains the integration-test boundary
- oversized production code must be decomposed by domain or architectural responsibility
- test-only extraction, arbitrary half-splits, and numbered fragments are explicitly forbidden

The rule is canonical in `.cortex`, exposed as the project source-file-size skill, and enforced by a typed Rust preflight scanner.

## Static enforcement

The scanner covers authored Rust, TypeScript/Svelte/JavaScript, shell, CSS, HTML/HTM, YAML/YML, and other source formats. It:

- applies 1,000/1,500 physical-line hard limits repository-wide
- detects external positive `cfg(test)` modules under `src`
- recursively handles nested inline modules and `all`/`any`/`not` cfg expressions
- detects test-gated `include!` files, including includes inherited from inline test modules
- preserves true crate-level integration tests
- scopes generated/output exclusions by provenance so authored `src/coverage`-style modules remain scanned

A dedicated `Source architecture` workflow runs the focused invariant test on every pull request without path filters, including product trees excluded from the standard product pipeline.
