# Refactor Neo4j claim retry and test boundaries

## Outcome

Squash-merged Nook PR 835. Neo4j transient-claim retry policy now has a focused
production owner with inline unit coverage. The public-store graph scenario is a
true crate-level integration test using public Hive APIs, and the obsolete
external unit-test module under `src` is gone.

## Progress

- Extracted claim retry classification and backoff into
  `neo4j/claim_retry.rs` with its unit test inline.
- Moved the graph-store workflow to `hive/tests/neo4j_store.rs`.
- Removed its dependency on private store internals by creating an independent
  Neo4j driver connection.
- Updated Hive formatter, check, and test stages to include integration tests.
- Updated the host formatter copy-back contract for `hive/tests`.

## Implementation problems

- Review correctly found that the first Dockerfile revision did not copy the new
  integration target into all verification stages.
- A later review found that container rustfmt output for `hive/tests` was not
  copied back to the host. Both P1 threads were fixed, replied to, and resolved.
- The CLI readiness audit was temporarily blocked by GitHub REST rate limiting;
  equivalent exact-head checks, review-thread audit, and base comparison were
  completed through the GitHub connector.

## Decisions

- Keep only retry policy as a unit-tested production abstraction under `src`.
- Treat the Neo4j public-store workflow as integration coverage because it
  exercises the crate through public APIs and an external database boundary.
