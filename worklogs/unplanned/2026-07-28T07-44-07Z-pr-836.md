# Refactor core validation and colocate unit tests

## Outcome

Squash-merged Nook PR 836. Secret-record filtering and secret-data validation
now live in the secrets domain with inline unit tests. Provider and storage
validation remain in the sync domain with their unit tests inline, and the
external Rust unit-test file was removed.

## Progress

- Added `secrets/validation.rs` for secret filtering and secret-data policy.
- Kept provider/storage policy in `sync/validation.rs`.
- Colocated all affected unit tests with their focused implementation modules.
- Removed `sync/validation_tests.rs`.
- Preserved stable crate-root exports for callers.

## Implementation problems

- Review correctly rejected the first placement of secret validation under the
  sync domain. The production abstraction and its tests were moved to
  `secrets`, then the review was replied to and resolved.
- A rebase onto the preceding Neo4j architecture PR invalidated the trusted
  native handoff. The fresh Native job rebuilt from source and took 13:57 while
  Verify/preview and WASM stayed within their improved range.

## Decisions

- Domain ownership is more important than a convenient mechanical split:
  secret policy belongs to `secrets`; provider/storage policy belongs to
  `sync`.
- Unit tests remain inline with each production abstraction.

## Validation

- `task format` passed after rebasing onto current `main`, including 454
  nook-core tests and 18 WASM Node tests.
- Exact-head run
  [30338627730](https://github.com/meta-secret/nook/actions/runs/30338627730)
  passed all repository-owned jobs.
- All review threads were resolved.
- GitHub comparison confirmed the head was one commit ahead and zero behind
  `main`.
- PR 836 was squash-merged as
  `0bf855e41dc8ecc1a616a8dc6889c6ef084f0674`.

Land the sync-provider-store domain split, then continue the non-Rust
architectural size migrations before enabling the hard repository gate.
