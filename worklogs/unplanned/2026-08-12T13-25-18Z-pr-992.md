# Work summary

## Outcome

Portable vault connection probing and enrollment/password gate decisions now
live in `nook-core` behind typed WASM enums. Browser storage, provider I/O,
reactive state, translations, and lifecycle effects remain in TypeScript. The
affected production owners are below 750 lines, with no mobile behavior added.

## Progress

- Added Rust decisions for remote enrollment reassessment, password lookup,
  and the final connect, password, enrollment-request, or approval-wait gate.
- Exposed the decisions through the typed vault-client policy WASM boundary.
- Extracted cohesive Rust and TypeScript connection owners from the oversized
  policy and secret workflow modules.
- Added colocated Rust behavior tests, actual WASM adapter tests, and a
  first-vault connection demo invariant.
- Moved the architecture enforcement guard with the extracted `loadDb` owner.

## Implementation problems

- The first hosted web check found that the extraction had removed the logger
  instance and WASM-record cleanup helper still used by secret mutations. Both
  retained utilities were restored to `secrets.ts`.
- The first hosted preflight run found an ownership test still reading
  `secrets.ts`. Its target moved to `connection.ts` with `loadDb`.
- Main advanced twice during delivery. Each rebase was conflict-free and the
  required pre-push contract was repeated before republishing.

## Decisions

- Rust owns portable connection state decisions; TypeScript executes browser
  and reactive side effects selected by the returned enum.
- Remote provider access and browser-local WASM resource cleanup remain in the
  TypeScript connection adapter because they depend on host capabilities.
- The 976-line reactive vault facade remains a later focused slice instead of
  being mixed into this connection-policy PR.
