# Normalize authored TypeScript absence semantics

## Outcome

Normalized application-owned TypeScript and Svelte absence to `undefined`
across the web app, shared vault UI, browser extension, mocks, and browser
tests. Narrow `null` uses remain only where browser, ambient declaration, or
third-party component contracts require them.

## Progress

- Replaced nullable application state, messages, navigation data, and component
  props with optional or `undefined` forms.
- Normalized nullable browser and URL API results at their ingress boundaries.
- Added a repository preflight invariant backed by TypeScript and Svelte syntax
  trees, with regression fixtures for scripts, markup expressions, templates,
  comments, strings, regular expressions, and postfix/division syntax.
- Documented the absence rule and its external-contract exceptions.
- Preserved and recorded the Sentinel invitation focus-restoration flow.

## Implementation problems

- A token-oriented first version of the guard could confuse authored code with
  comments, strings, templates, and regular expressions. Review exposed those
  false positives, so the guard was replaced with syntax-tree parsing.
- A later review found that Svelte markup expressions and division following
  postfix operators needed explicit coverage. The parser traversal and fixtures
  were expanded before merge.
- Bits UI DOM reference adapters require `null` at their component boundary;
  using `undefined` there failed the Svelte build. Those exceptions remain
  narrow and documented.
- Concurrent changes advanced `main` twice during delivery. The branch was
  rebased and revalidated on each current base.

## Decisions

- `undefined` is the application-level absence convention; `null` is not banned
  when an external contract explicitly requires it.
- The regression guard parses authored syntax instead of matching source text,
  avoiding policy violations from non-code text while still covering Svelte
  markup expressions.
- Generated bindings, ambient declarations, WebAuthn signatures, and required
  component-library adapters remain compatibility boundaries rather than being
  rewritten.
