# Reactive PR Steward events for concurrent local Gizmos

## Outcome

Delivered and merged a self-hosted Argo Events and Core NATS WebSocket path that lets every local Gizmo run its own short-lived PR Steward subscriber for exactly one active pull request. PR #1492 was squash-merged as `a0d3b28f7ff8af06d9e9f2dab0cd35d5271e0d15`.

## Progress

- Reused the single repository-owned persistent JetStream cluster; no second NATS deployment or public raw NATS port was introduced.
- Exposed trusted TLS WSS at `events.dev.nokey.sh:443` while keeping NATS services and ports private inside Kubernetes.
- Added scoped subscribe-only PR Steward credentials and local synchronization to `~/.nook/events/pr-steward-client.yaml` with private file permissions.
- Added the official Core NATS client and a direct foreground subscriber that requires an immutable positive `--pr`, filters before stdout, emits minimal NDJSON, and drains on shutdown.
- Documented one independent child and subscription per Gizmo, with stop-drain-exit before the same Gizmo advances to another PR.
- Proved concurrent subscribers independently: stopping subscriber A did not interrupt subscriber B.

## Implementation problems

- An early pod design shared a process namespace and exposed the primary secret to a reloader sidecar. SRE removed the reloader, separated UIDs, and limited the key to the main container before acceptance.
- The first shutdown command used a package-script wrapper, causing Ctrl-C to exit the wrapper with status 1. The command was changed to a direct foreground Bun process; both concurrent clients then drained and exited 0 independently.
- Hosted repository policy rejected a multiline inline `bun -e` WSS checker. SRE extracted it into the tracked `infra/jetstream-wss-check.ts` program; the parser suite and live WSS security smoke then passed.
- Moving `main` required rebasing replacement heads before validation. Exact-head evidence was discarded and reacquired after each head change.

## Decisions

- Core NATS subscriptions use fan-out semantics, never a queue group, durable consumer, shared cursor, shared lock, or persistent PR Steward service.
- Every Gizmo owns one active, immutable PR subscription at a time. Multiple Gizmos may subscribe concurrently to different or identical PRs without stealing events.
- Notifications are best-effort hints. The final PR lifecycle step always reconciles GitHub directly, so missed events do not become authoritative state.
- Public access is WSS-only with scoped credentials and deny-by-default publishing and subscription permissions.
