# PR Steward independent Team Agent context

## Outcome

PR Steward is now an independent operational Team Agent context using the fixed
`gpt-5.6-luna` and `xhigh` profile. Gizmo delegates explicitly authorized,
mechanical pull-request operations to that context instead of loading the
growing pull-request lifecycle knowledge into Gizmo or a shared skill.

## Progress

- Added the PR Steward authority, knowledge graph, lifecycle workflow, and
  exact-head authorization handshake.
- Routed Cortex discovery and Loom context composition directly to the new
  Team Agent context and added focused ownership and isolation tests.
- Added delegation-visualization support for the `pr-steward` team.
- Removed the obsolete Gizmo-owned PR Steward workflow.
- Added a fail-closed administrator squash route for required deployments that
  are intentionally excluded by repository path policy.
- Squash-merged Nook PR 1434 as
  `7c752990c611ab9afb04708dd4780d4a7e7ef34b`.

## Implementation problems

- The first hosted policy run found that the generated Cortex index inventory
  did not include the new independent context. The deterministic index and its
  exact assertion were updated.
- The next hosted policy run found an executable-skill-host fixture that still
  expected the old tool description. The exact fixture was updated.
- A later hosted run had one unrelated module-expert test time out after five
  seconds while 677 other tests passed. One unchanged-head failed-jobs rerun
  passed.
- The ordinary protected-branch merge was blocked because `github-pages` is
  required but intentionally does not run for Cortex-only paths. The existing
  bounded administrator route was made explicit in PR Steward policy and used
  only after exact-head readiness passed.

## Decisions

- PR Steward is a real separately composed Team Agent context, not a Gizmo
  skill and not a sixth functional product authority.
- Gizmo retains mission control, functional adjudication, shared-branch
  sequencing, Workbench ownership, and the final readiness verdict.
- Every PR Steward operation requires a bounded packet naming the PR, exact
  head, permitted operation, and return evidence. Merge requires a separate
  packet.
- PR Steward may perform mechanics and collect evidence but may not edit
  product code, adjudicate findings, or invent deployment evidence.
