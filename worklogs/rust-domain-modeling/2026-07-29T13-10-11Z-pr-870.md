# Rust ecosystem quality gates delivered

## Outcome

Nook now uses cargo-deny and RustSec for dependency policy and advisories,
Proptest and Insta for generated and snapshot assertions, Loom for bounded
concurrency schedules, cargo-fuzz for parser fuzzing, Kani for bounded proofs,
and Dylint for reusable typed repository lints.

## Progress

- Added a label-gated, scheduled, and manually dispatchable Rust ecosystem
  workflow with bounded jobs and pinned compiler-coupled toolchains.
- Added policy/configuration for licenses, registries, Git sources, snapshots,
  fuzz targets, Dylint, and all four independent Cargo workspaces.
- Seeded property, snapshot, Loom, fuzz, and Kani coverage in the replication
  and wire-parser domains.
- Updated Cortex and the public check catalog with benefits, cost tiers, and the
  ecosystem-first boundary for bespoke preflight.
- Extended exact-head readiness and path classification for Cargo
  configuration, preflight, and Minds.
- Applied Dylint-discovered transactionality repairs for provider credentials,
  event-log union, and passkey mutation; added behavior-focused rollback tests.

## Implementation problems

- `cargo-fuzz run` does not accept Cargo's `--locked` flag. The workflow now
  uses locked Clippy plus an explicit `cargo metadata --locked` preflight before
  invoking the pinned fuzzer.
- RustSec found two Hickory denial-of-service advisories through the pinned
  upstream Codex/Rama graph. Current upstream Codex still uses Hickory 0.25.2,
  so both IDs are narrowly documented in cargo-deny, cargo-audit, and the audit
  action instead of being hidden.
- Review and Dylint exposed real mutation-before-validation paths. The affected
  code now validates cloned or staged state before committing it.
- Several complete validation runs became stale as findings were corrected and
  `main` advanced. The final head was rebased and revalidated from scratch.

## Decisions

- Ecosystem tools own generic Rust guarantees; custom preflight remains only
  for Nook-specific architecture and workflow invariants.
- Long fuzz campaigns remain scheduled/manual, while PR fuzzing is a bounded
  smoke test with retained corpus/crash artifacts.
- Nightly, cargo-fuzz, Kani, and Dylint versions are pinned so unchanged heads
  retain reproducible compiler behavior.
- Advisory exceptions must name exact RustSec IDs, the upstream graph, and the
  dependency upgrade that removes them.
