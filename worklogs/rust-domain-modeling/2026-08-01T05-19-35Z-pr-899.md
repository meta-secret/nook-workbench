# Eliminate authored Rust macros

## Outcome

Nook now prohibits repository-authored declarative and procedural Rust macros.
All seven existing authored macro definitions were replaced with explicit
structs, enums, implementations, deserializers, and control flow. Compiler and
ecosystem derives and attributes, standard library macros, and purpose-built
external code generation remain allowed integration boundaries.

## Progress

- Added the critical Cortex rule, a durable dynamic skill, and agent skill
  mirrors describing the macro-free authored-source boundary.
- Expanded Hive identifier, error, bail, and ensure macros into ordinary Rust.
- Expanded core wire parsing, sync-state enums, and authentication/vault string
  newtypes into explicit implementations.
- Added syntax-aware preflight enforcement for declarative and procedural macro
  definitions across authored repository Rust.
- Hardened the repository walker after security review so directory and Rust
  file symlinks cannot escape the scan root.
- Squash-merged Nook PR #899 as `c6619ef6225247db926396ca32fd961be654771b`.

## Implementation problems

- The first hosted preflight run found a Clippy-only raw-string lint in the new
  guard test; the literal was simplified and the rerun passed.
- Security review found that the recursive scanner followed symlinks. The
  walker now skips symlinks before recursion or file reads, with regression
  coverage for both directory and `.rs` symlinks.
- Hive verification found three `needless_return` cases left by macro expansion.
  They were converted to tail expressions without changing behavior.

## Decisions

- The repository target is zero authored Rust macro definitions, enforced
  mechanically rather than as a subjective review preference.
- Small, explicit boilerplate is preferred over local macro abstraction.
- External derives, attributes, standard formatting/assertion/collection
  macros, and `quote!`-style code generation remain allowed when code generation
  is the actual ecosystem or compiler boundary.
- Symlinks are excluded from the authored-source scan instead of canonicalized
  and followed, preserving repository containment.
