# Validated Sentinel share versions

## Outcome

PR 1364 was squash-merged as `37d8d5ea4657549a56857cd18278516a46e780d9`, with 563 authored additions excluding lockfiles.

## Progress

- Added `SentinelShareVersion`, preserving supported numeric wire values 1 and 2 while rejecting zero, future, and overflowing values.
- Made reserved Sentinel-share record classification fallible so malformed metadata cannot be reclassified as a domain secret or silently omitted.
- Propagated parse failures through Auth2, Core, Event Log, and WASM ingestion paths.
- Staged metadata and ceremony state before fallible replacement, checkpoint replay, rewrap, and session installation.
- Added version, classification, YAML, checkpoint, and ceremony-state regression coverage.

## Implementation problems

- Hosted checks exposed three test-compilation errors, two redundant `must_use` attributes, and one invalid WASM test fixture; each replacement head was repaired narrowly and revalidated.
- Main advanced four times during delivery. Three updates merged cleanly; Sentinel genesis typestate work conflicted in one Auth2 file and was resolved by preserving Main's typestate flow while retaining this PR's fallible classifier.
- Exact-head validation was repeated after every code or base change. The final run passed on the current Main head.
- The external review service reported its usage limit. Existing feedback contained no substantive findings, and repository readiness passed under its inspect-existing-feedback policy.

## Decisions

- Keep the serialized numeric shape and supported legacy/current versions; enforce validity at deserialization.
- Treat malformed reserved Sentinel metadata as an error, without a recovery bucket, compatibility parser, or fallback classification.
- Preserve Main's consuming Sentinel genesis typestate API and adapt its issuance path to fallible classification.
- Keep Auth2 lint activation as a separate, smaller crate-onboarding PR.
