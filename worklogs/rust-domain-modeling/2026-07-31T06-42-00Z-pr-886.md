# Extract companion WASM and finish domain-boundary cleanup

## Outcome

Merged [Nook PR #886](https://github.com/meta-secret/nook/pull/886). Structured
login-context observations replace loose string bags, vault-app OAuth call sites
use generated WASM enums instead of TypeScript mirrors, and content-script /
host-policy heuristics now load a tiny `nook-companion-wasm` package instead of
mirroring those rules in TypeScript.

## Progress

- Introduced `LoginContextObservation` for `has_login_context` inputs.
- Deleted TypeScript OAuth enum mirrors; vault-app uses generated
  `BrowserOAuthProvider` / `OAuthOriginUnsupportedReason` types.
- Extracted `nook-companion-core` and thin `nook-companion-wasm`; full vault
  `nook-wasm` remains for background, popup, and vault apps.
- Wired extension content scripts and Manifest/Node host-policy adapters through
  companion WASM init; dual-package Docker/CI handoff nests companion under the
  vault WASM artifact tree.
- Updated UI demo assertions for WASM OAuth policy on local preview hosts.

## Implementation problems

- Knip and preflight needed companion-package ignores and generated-pkg skips.
- Unit tests required a companion WASM fetch stub in the shared setup.
- iCloud OAuth demo initially assumed support on `127.0.0.1`; WASM policy rejects
  that origin, so the demo asserts the unsupported banner instead.
- Exact-head validation was blocked briefly by registry hostname/DNS cutover on
  main; rebased onto the `registry.dev.nokey.sh` lineage and revalidated green.

## Decisions

- Keep OTP keyword tables as string tables; classifier API inputs stay structs.
- Do not inject full vault WASM into content scripts.
- Leave CLI/mobile out of scope; no rebuild of those surfaces.
