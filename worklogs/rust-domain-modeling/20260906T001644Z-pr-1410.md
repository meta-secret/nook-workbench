# Nook Core numeric vault API prerequisite

## Outcome

PR 1410 was squash-merged as `81a3fc171a0af5d157341eef90d6092e5a47a3ab`, with 1,305 authored additions excluding lockfiles.

## Progress

- Migrated all 69 genuine raw-numeric Nook Core declarations in the planned vault/sync surface to 24 private-storage domain types.
- Covered BIP39, import and presentation counts, authenticator time, file sizes, vault policy and paging, catalog buckets, runtime timing, Sentinel values, and persisted versions.
- Preserved scalar serialization, database values, JavaScript projections, overflow behavior, and Core/WASM consumers.

## Implementation problems

- The first expanded hosted run found one missing internal reexport and two invalid const conversions; all three were corrected.
- The second hosted run proved that activating Nook Core also audits 57 raw contracts inherited through its stable external facade. Use-item suppression is intentionally forbidden, so activation was held behind a later typed-facade migration instead of weakening the lint or exceeding the fixed PR budget.
- Six exact Clippy failures in WASM consumers were corrected.
- Main advanced during implementation and was merged before final validation.

## Decisions

- Expanded the original micro-slice into one 1,305-addition prerequisite cohort while preserving the user-set 1,500-addition ceiling.
- Keep reachable external reexport enforcement intact; do not introduce blanket or facade suppressions.
- Record Core activation as pending on inherited facade contracts while retaining the completed vault/sync domain migration.
