# Rust domain-state and unwrap refactor

## Outcome

PR 796 was squash-merged. Required encrypted-secret fingerprints are validated
non-empty values; revision, workflow, actor-key, device/PIN, session, and Hive
wire-result states are explicit; and authored Rust contains no `.unwrap()` or
`.unwrap_err()`. Tests propagate setup errors with `anyhow::Result`, while
production domain errors remain concrete `thiserror` types.

## Progress

- Reviewed the full authored Rust `Option<T>` occurrence set and removed the
  invalid domain absence covered by this delivery.
- Made `identity_fingerprint` and `fingerprint` mandatory without a legacy
  fallback or backfill path.
- Preserved the two distinct fingerprint invariants: logical-item identity
  excludes the secret, while the exact-version fingerprint includes it.
- Replaced unwrap-based test setup and assertion plumbing across Nook,
  preflight, Hive, and Lace; enabled repository-wide Clippy unwrap denial.
- Updated Cortex rules and the Rust coding skill so tests use typed `Result`
  propagation and never use boxed dynamic errors as a convenience alias.

## Implementation problems

- The initial pass was too narrow for the repository-wide request. Subsequent
  passes expanded the audit to all authored Rust workspaces and added mechanical
  enforcement so missed unwraps cannot recur.
- Several strict conversions exposed real lifecycle requirements: Sentinel
  ceremony sessions must survive failed finalization, PIN mode must cross the
  WASM boundary explicitly, and Hive terminal payloads require validation at
  deserialization.
- `main` advanced twice during final delivery. Both rebases were followed by
  fresh exact-head format, audit, GitHub Actions, and readiness gates.

## Decisions

- `Option<T>` remains only where absence is structurally truthful, such as
  lookup/parser results, optional caller input, and external boundary shapes.
- Required persisted and signed fields use validated values; named lifecycle
  and authorization states use enums whose variants own their valid data.
- Tests use `anyhow::Result` for ergonomic `?`; production libraries expose
  concrete typed errors with `thiserror`.
- No compatibility DTO, legacy fallback, or synthesized fingerprint value was
  retained.

## Validation

- `task format` passed on the final rebased head.
- Repository audit found zero authored Rust `.unwrap()`/`.unwrap_err()` and
  zero `Box<dyn Error>` aliases.
- Exact-head GitHub Actions runs
  [PR 30251044422](https://github.com/meta-secret/nook/actions/runs/30251044422)
  and [Hive 30251044318](https://github.com/meta-secret/nook/actions/runs/30251044318)
  passed.
- `task pr:ready PR=796` reported behind-by zero, mergeable, successful preview
  deployment, and zero unresolved review threads.
