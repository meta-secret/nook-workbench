# Establish the Nook Security Team

## Outcome

Pull request 1166 is squash-merged as
`495a14cd7f172918e689fba9838af80c9d6c701f`. Cortex now has a Security team
with selective context routing, security-owned architecture and skills, and an
evidence-backed inventory of Nook's implemented cryptographic mechanisms.

## Progress

- Added the Security team contract and concise knowledge graph.
- Moved security-primary identity, secret-store, vault-session, browser-release,
  and user-facing security authorities into the Security team.
- Kept mixed product specifications and implementation with development core,
  web development, SRE, and AI.
- Documented protected assets, trust boundaries, key separation, authorization,
  recovery, operational controls, limitations, algorithms, record versions,
  parameters, and source evidence.
- Extended Loom, Workbench, module-expert, and preflight ownership validation
  for the fifth team.

## Implementation problems

- Cross-indexing Security documents from development-core and web-development
  graphs violated the one-owner graph contract. Narrow read-only links now live
  in team contracts while every document remains in exactly one graph.
- Team ownership was encoded in several deterministic allowlists. The routing,
  graph validator, skill scaffolder, Workbench validator, and tests were updated
  together.

## Decisions

- Security owns cross-team security invariants, architecture, cryptographic
  inventory, and acceptance evidence. Functional teams retain implementation.
- Only security-primary documents and skills moved. Documents that merely
  contain security-sensitive behavior remain with their functional owner.
- The cryptographic reference distinguishes native Nook formats from algorithms
  used only for third-party import compatibility.
- Documentation states observed repository behavior and limitations; it makes
  no audit, compliance, or formal-verification claim.
