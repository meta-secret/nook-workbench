# Own multi-device key and record actions

## Outcome

Multi-device vault-key generation, compact identifiers, public-key derivation, auth-envelope parse/issue/resolve, age sealing, and record classification now live on owned domain types and a borrowed record-view owner. All direct auth2, core, WASM, and test callers use those owners, and PR #1543 merged successfully.

## Progress

- Added the owned multi-device key and record action module with exact ownership denial and invalid-suppression prohibition.
- Migrated the auth2 state, join, access, roster, Sentinel, identity, core, and WASM call sites.
- Removed detached compatibility functions and exports for the migrated operations.
- Preserved wire rows, aliases, encryption, error ordering, record ordering, and mutation semantics.

## Implementation problems

- The first hosted heads exposed stale direct imports and call sites after the free-function removal; the callers were migrated before the final validation.
- Strict Clippy found `double_must_use`, elidable lifetime, and missing `must_use` annotations in the new owner module; these were repaired.
- Final WASM Node validation found one needless borrow and one missing `VaultKeys` import; both were corrected on the merged head.
- Main advanced during delivery; the final PR was rebased onto base `7d8c1b9833995f9ca3b7e066662e117ec2655f44` before final checks.

## Decisions

- Reused the existing Cortex action-ownership policy; no new policy text was needed for this closure.
- Used simple consuming and borrowed owners rather than introducing a generic typestate framework; richer states remain reserved for boundaries with concrete lifecycle invariants.
- Kept schema, ABI, cryptographic algorithm, authorization, persistence, fallback, recovery, and retry behavior unchanged.
