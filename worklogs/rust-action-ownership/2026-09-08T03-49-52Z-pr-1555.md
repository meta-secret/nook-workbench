# Work summary

## Outcome

PR #1555 moved Sentinel genesis operation construction, simple identity roster emission, recovery-option projection, and recovery device hint formatting onto existing Rust domain owners. Core and WASM callers now use associated actions, and the PR squash-merged at `abd11e60130cda8b34eb406f176ee97ff8dfb775`.

## Progress

- `SentinelGenesisOutput` owns operation construction; `SimpleIdentityGenesisOperationsInput` owns identity operation construction; `VaultRecoveryOptions` owns graph-based recovery projection; and `VaultRecoveryDevice` owns passkey hint formatting.
- Direct core and WASM onboarding, passkey, diagnostics, and event-log callers use the owning methods while public adapters and wire behavior remain unchanged.
- Completed modules deny homeless production functions and reject invalid ownership-lint suppressions. The lint permits ordinary free helpers in positively `cfg(test)`-gated scopes, as requested, while still checking explicit boundary expectations.
- Delivered 546 authored additions in one cohesive slice.

## Implementation problems

- The Dylint implementation initially coupled HIR and item lifetimes, then required a request-lifetime correction and a nightly `BytePos` API correction.
- Test-only detection cannot rely on HIR `cfg` attributes after configuration stripping, so the final rule scans the source configuration enclosing the item and accepts only positive `cfg(test)` or test-only `cfg(all(...))` predicates. Coverage tests were added after the linter fell just below the repository floor.
- Review feedback repeatedly requested fixture ownership; the user clarified that test code may intentionally contain free helpers, so test-only namespaces remained unchanged while production ownership enforcement was tightened.

## Decisions

- Preserved event operation ordering, enrollment validation, labels, encrypted envelopes, recovery redaction, revocation and rename handling, passkey hint strings, DTOs, and public adapter behavior.
- Used existing domain owners and a typed recovery projection request without introducing a generic phase framework or changing provider, storage, authentication, or cryptographic behavior.
- Kept the onboarding and recovery actions together as one cohesive PR rather than splitting them into micro PRs.
