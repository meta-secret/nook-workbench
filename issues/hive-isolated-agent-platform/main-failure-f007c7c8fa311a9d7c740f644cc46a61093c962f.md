## Findings and decisions

- Main failure records include job names and workflow links, never raw logs or
  credentials.
- The failed identity-recovery regression removed only protected app-key
  records while leaving the identity directory behind. That impossible state
  prevented the login gate from settling. The repair uses production recovery
  and verifies that known-vault evidence survives the reset.
- The failed routing regression combined browser Back, reload, and
  authentication in one timing-sensitive journey. The repair preserves route
  allocation and isolates actual Back/deep-link behavior in focused coverage.
- An extra Access-tab click after the completed access-chain journey was flaky
  and did not contribute to that regression's behavior assertion.
- PR 1064 already contained the failed revision as its direct parent and
  delivered this exact repair while the f007c7c8fa31 Main run was still in
  progress. A duplicate repair branch or PR would add no source change.
- Final review feedback was delivered through PR 1066 before the original
  review threads were resolved.
