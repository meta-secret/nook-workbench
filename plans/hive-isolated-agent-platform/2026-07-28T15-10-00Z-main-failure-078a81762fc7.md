# Main verification repair plan

## Interpreted request

Restore default-branch browser verification after the recorded Main run failed,
using a focused Nook pull request that preserves the incident evidence and
lands only after its exact-head checks succeed.

## Requirements

- Diagnose the failed web and extension browser jobs from the retained run.
- Implement the smallest behavioral correction and a regression test for the
  observed path.
- Label the repair PR `ci:full-e2e`, resolve existing actionable feedback, and
  squash-merge only after repository-owned checks and readiness auditing pass.
- Record the repair result, validation, and agent statistics in Workbench.

## Constraints and exclusions

- Keep the failed revision and workflow link in the incident record.
- Do not bypass checks, change cache isolation, expose sensitive data, or push
  directly to the default branch.
- This work is limited to the failure root cause and its regression coverage.

## Initial plan

1. Inspect the failed jobs, retained artifacts, and current Main state.
2. Publish this plan, prepare the deterministic repair branch, and isolate the
   shared failure mechanism.
3. Add the minimal correction with browser-level regression coverage.
4. Format, push, label and validate the PR, then resolve feedback and merge.
5. Verify the resulting Main run and publish the incident completion worklog
   and statistics.

## Completion evidence

- A linked repair PR with the full-e2e label, green exact-head repository
  checks, and successful squash merge.
- A successful resulting Main workflow plus Workbench incident and worklog
  records that link the repair and validation.

## Safety review

This plan contains no raw prompt, chat transcript, secrets, private data, raw
logs, local paths, or unnecessary infrastructure details.
