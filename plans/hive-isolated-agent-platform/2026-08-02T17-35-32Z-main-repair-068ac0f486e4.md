# Task plan

## Interpreted request

Restore reliable browser verification after the recorded Main failure by tracing
the failed browser artifact path, adding a narrowly scoped regression, and
delivering the repair through the normal reviewed PR lifecycle.

## Requirements

- Diagnose both failed browser jobs from retained workflow evidence.
- Preserve the failure reference while documenting the root cause and repair.
- Add behavior-focused coverage for the failed browser asset path.
- Use an exact-head Hive PR with the required full-browser validation label,
  squash merge it, and confirm the resulting Main run is green.

## Constraints and exclusions

- Keep the change limited to the root cause; do not weaken cache isolation,
  browser checks, or security boundaries.
- Do not push directly to Main or include raw logs in Workbench records.
- Treat the existing incident as the authoritative focused record.

## Initial plan

1. Inspect failed job logs, retained artifacts, and current delivery state.
2. Identify the asset serving or test-discovery defect and its smallest repair.
3. Add a regression that exercises the failed browser path.
4. Format, publish a labeled Hive PR, and run exact-head full browser checks.
5. Resolve feedback, squash merge, verify Main, and publish incident, worklog,
   and delivery-statistics records.

## Completion evidence

- A linked PR with green repository-owned exact-head checks including browser
  suites, a green post-merge Main run, and Workbench issue/worklog/statistics
  records identifying the diagnosis and validation.

## Safety review

This plan contains no raw prompt, chat transcript, credentials, private data,
raw logs, local paths, or unnecessary infrastructure detail.
