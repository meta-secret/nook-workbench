# Main browser verification repair plan

## Interpreted request

Restore reliable default-branch browser verification after the recorded Main
failure, using one scoped Nook pull request and completing its full review,
merge, and resulting Main-validation lifecycle.

## Requirements

- Diagnose retained Main evidence for the failing web and extension browser jobs.
- Make the smallest root-cause change with a behavior-focused browser regression.
- Publish a normal PR, label it `ci:full-e2e`, satisfy exact-head checks and
  feedback, then squash-merge it.
- Preserve the incident evidence and publish completion context and PR
  statistics in Workbench.

## Constraints and exclusions

- Do not change Main directly, bypass checks, or weaken security or cache
  boundaries.
- Treat the pinned failed revision as incident evidence while rebasing the
  repair on current Main.
- Workbench records contain only public-safe summaries and links, not raw logs
  or credentials.

## Initial plan

1. Inspect existing branch, PR, Main runs, retained failures, and incident state.
2. Isolate the shared browser failure and add a focused regression.
3. Format, publish the deterministic repair branch and PR, and enable full E2E.
4. Resolve repository checks and feedback, audit the exact head, squash-merge,
   then verify the resulting Main run.
5. Record the outcome, worklog, and statistics in Workbench.

## Completion evidence

- A merged squash PR with green repository-owned full browser checks and a
  green resulting Main workflow.
- Updated incident, linked worklog, and immutable PR statistics record.
