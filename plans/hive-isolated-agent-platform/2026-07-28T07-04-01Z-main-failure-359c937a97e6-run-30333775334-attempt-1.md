# Task plan

## Interpreted request

Restore a green default-branch integration after the retained browser and UI-demo
failures introduced with the popular-login fixture-generator split, using the
normal reviewed repair lifecycle.

## Requirements

- Diagnose the retained Main evidence and make the smallest root-cause repair.
- Add behavior-focused regression coverage for the missed browser-facing path.
- Publish a normal repair PR carrying the full browser-validation label, resolve
  current actionable feedback, squash-merge, and verify the resulting Main run.
- Record the completed delivery and validation in Workbench without raw logs or
  sensitive data.

## Constraints and exclusions

- Preserve the failing revision and its workflow evidence; do not bypass checks,
  weaken cache boundaries, or push directly to the default branch.
- Use GitHub Actions as the product gate and the guest PR readiness audit.
- The repair is limited to the demonstrated failure mechanism; unrelated
  refactoring is excluded.

## Initial plan

1. Inspect the failed jobs, artifacts, current GitHub state, and fixture changes.
2. Reproduce or isolate the common failure mechanism and implement a focused fix
   with a browser regression.
3. Format, publish the deterministic branch and labeled PR, and monitor exact-head
   repository checks plus existing feedback.
4. Refresh against Main if needed, run the guest readiness audit, squash-merge,
   verify the replacement Main run, then publish Workbench completion records.

## Completion evidence

- A squash-merged repair PR with the full browser suites green at its exact head.
- A successful replacement Main run and updated incident, worklog, and agent
  statistics records on Workbench.

## Safety review

This plan contains only a concise operational summary. It excludes raw prompts,
logs, credentials, private data, local paths, and unnecessary infrastructure
