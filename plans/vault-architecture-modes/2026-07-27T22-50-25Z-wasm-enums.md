# Task plan

## Interpreted request

Make the Rust-owned vault architecture taxonomy cross the WASM boundary as
actual enum values so browser code cannot construct vault types from arbitrary
string literals.

## Requirements

- Export vault type as a real Rust/WASM enum rather than a TypeScript string
  union.
- Remove handwritten vault-type literals from Svelte state and flow actions.
- Apply the same boundary correction to the adjacent device-mode and
  replication-type enums when required to keep the architecture API coherent.
- Preserve serialized wire values and persisted compatibility.
- Add focused regression coverage for the generated enum boundary and default
  architecture values.
- Deliver through the normal pull request, GitHub Actions, review-resolution,
  squash-merge, and Workbench closeout workflow.

## Constraints and exclusions

- Rust remains the source of truth for architecture taxonomy and validation.
- Existing serialized kebab-case values and stored vault formats must not
  change.
- No visual redesign or product behavior change is intended.

## Initial plan

1. Audit Rust, WASM, generated TypeScript, and Svelte call sites for stringly
   typed architecture modes.
2. Export concrete WASM enums and update browser consumers to use enum members.
3. Add boundary-focused tests and remove obsolete parsing paths where safe.
4. Format, validate through GitHub Actions, address feedback, and squash-merge.
5. Publish the linked worklog and agent statistics.

## Completion evidence

- Generated bindings expose enum objects and authored browser code uses enum
  members instead of vault architecture string literals.
- Rust and web checks pass on the exact pull-request head.
- The pull request is squash-merged and linked Workbench records are published.
