# Rebuild executable skill reachability as four focused layers

## Interpreted request

Keep the completed lower GitHub stack, retire the oversized reachability pull
request, and reconstruct its preserved behavior as dependency-correct pull
requests that are easy to review and merge. Continue later executable-skill
work only after these layers are green. Treat authored HTML in Cortex Markdown
as prohibited input, so no HTML or browser parser belongs in this stack.

## Requirements

- Keep every immediate-base pull request strictly below 5,000 changed lines.
- Target 3,000 changed lines or fewer and preserve review-fix headroom.
- Keep every authored file at or below 1,000 lines.
- Use GitHub stacked pull requests and merge green lower layers before advancing.
- Preserve fail-closed evaluator, loader, configuration, action, subprocess,
  symlink, shell, and extensionless-script evidence.
- Request exact-head hosted review and complete repository validation for every
  implementation layer.
- Keep the executable provider dormant until the activation layer.
- Prohibit authored HTML in Cortex Markdown and do not add an HTML parser.

## Constraints and exclusions

- No Docker-in-Docker, nested daemon, or host Docker socket mount is allowed.
- The oversized PR #1108 is preservation evidence, not a branch to merge.
- The dirty loader-provenance worktree is not an implementation source and must
  remain untouched.
- Obsolete Cortex article and HTML-parser changes are excluded.
- Published predecessor plans remain immutable; this plan supersedes the
  fourteen-slice plan for the remaining sequence.
