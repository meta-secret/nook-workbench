# Consolidate self-improvement into the Loom graph skill

## Interpreted request

Make the self-improvement skill the canonical operational guide for learning
from substantial work. It must include a repeatable audit that extracts stable
mechanical workflow steps from Cortex into reviewed Loom TypeScript graphs.
Remove duplicated instructions from general Cortex entry points and workflows.
Replace misplaced repository-shell enforcement with a Loom-owned TypeScript
implementation when the current runtime boundary supports it.

## Requirements

- Audit the self-improvement rules introduced by the prior change against all
  active Cortex workflow and delegation authorities.
- Centralize reusable self-improvement policy in the dynamic skill.
- Keep general entry points concise and link them to the canonical skill.
- Define how agents classify Markdown instructions as semantic judgment,
  deterministic leaves, parallel worker tasks, parent-only mutations, or unsafe
  automation.
- Require independent safe work to be delegated and joined by one delivery
  owner.
- Teach agents to propose or implement reviewed static Loom workflow graphs
  when a repeated stable procedure qualifies.
- Move session-clean enforcement into Loom TypeScript if that preserves the
  current readiness contract.
- Add behavior and structural coverage for changed workflow boundaries.

## Constraints and exclusions

- Loom workflow topology remains reviewed TypeScript. Markdown and YAML do not
  define runtime graph shape.
- Cortex continues to own policy and semantic judgment.
- Loom and Task own deterministic execution and mechanical validation.
- Child workers remain read-only or use isolated disjoint write scopes.
- One task-owning agent retains Workbench, branch, pull-request, review,
  validation, readiness, and merge authority.
- Do not weaken session cleanup or allow temporary memory into version control.
- Do not modify foreign active task state.
