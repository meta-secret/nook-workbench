# Centralize shared Rust localization infrastructure

## Interpreted request

Remove the separate generated localization-key files from `nook-core` and
`nook-auth2`. Introduce a leaf-level shared Rust crate that owns the canonical
locale catalogs, translation utilities, and single generated key registry, then
make higher-level application crates consume or compatibility-re-export that
one implementation.

## Requirements

- Add `nook-app-common` as a workspace crate below both `nook-auth2` and
  `nook-core` in the dependency graph.
- Move the English and Russian catalogs, translation behavior, and generated
  Rust key registry into the shared crate.
- Generate exactly one Rust key file while preserving the existing generated
  TypeScript registry and catalog-parity enforcement.
- Migrate `nook-auth2`, `nook-core`, WASM callers, tests, Docker/build inputs,
  coverage, and architecture enforcement to the new ownership boundary.
- Preserve public compatibility where a direct `nook-core` re-export prevents
  unnecessary downstream churn without preserving duplicate source.
- Add mechanical enforcement that rejects recreated per-crate key copies.

## Constraints and exclusions

- `nook-app-common` is a narrow leaf crate for dependency-light application
  primitives shared by sibling crates, not a miscellaneous home for unrelated
  domain code.
- Authentication policy remains in `nook-auth2`; vault semantics remain in
  `nook-core`; browser interop remains in `nook-wasm`.
- Translation text and observable locale behavior must not change.
- No user-interface design or interaction changes are included.

## Initial plan

1. Inventory localization ownership, crate edges, generation paths, Docker
   inputs, tests, and preflight assumptions.
2. Create `nook-app-common`, move catalogs and localization implementation, and
   expose the single generated key module.
3. Update consumers and the generator, delete both old generated copies, and
   strengthen architecture enforcement.
4. Host-apply formatting, commit, push, and open a focused PR.
5. Run focused hosted Rust/WASM/web validation, then complete exact-head PR
   validation, address existing feedback, and squash-merge when ready.

## Completion evidence

- Only `nook-app-common` contains a generated Rust localization-key registry.
- `nook-auth2`, `nook-core`, and WASM compile and pass behavior-focused tests
  through GitHub-hosted validation.
- Generator drift checks and preflight reject duplicate Rust registries.
- Exact-head repository workflows, deployment, feedback audit, and
  `task pr:ready` pass before squash merge.
